# 交付之后的阶段：定点 patch + 一致性审计 + 补充图 QA

适用：已经交付过一版返修材料，用户拿走后**重命名 / 手工清理 / 提出"只检查不改"的要求**，随后又让你只改其中几项。

---

## 1. 用户手工编辑过的交付文件：只能定点 patch

本 session 实况：用户把 `01_Manuscript_JCEH_revised.docx`→`Manuscript_revised.docx`、`02_…`→`Point-by-point response.docx`、`03_…`→`Title_Page_revised.docx`、`07_…`→`Figure_Legends_revised.docx`，并做了一次全局"特殊字符→ASCII"清理（en dash→连字符、弯引号），还删掉了手稿末尾的 Figure legends 整节。

### 硬规则
1. **禁止重跑构建脚本。** 重跑会用你的版本覆盖掉用户的手工改动（重命名、删节、符号风格）。
2. **改在用户当前文件上做 run 级替换**，不要 `set_text` 整段重写——那会压平上标引用、粗体 `P`、上下标 `2`（kg/m²）。
3. **先 dump `段落.runs` 再改。** 目标串常被拆进多个 run：
   `'Hochberg correction (FDR 0.0012'` + `'0.011).'`；`'= 0.004.'` 单独一个 run。
   按 run 定位并逐 run 改写，改完**回读整句**。
4. **改前 `cp -r` 整个交付夹做备份**；改后用 `difflib.SequenceMatcher` 逐段对照备份，在报告里证明"只改了这几处"。
5. **路径替换必须断言。** 脚本里 `OUT` 有两种写法——`OUT = r"...\<夹名>"` 与 `OUT = r"...\<夹名>\<文件名>"`；按"夹名前缀"替换后要 `assert PREFIX in src`，否则脚本会把文件写回用户的交付夹（本 session 因此误建过一个文件，事后删掉并如实告知）。
6. **删词句会改变字数。** 本 session 删掉的半个句子恰好 **17 词**，标题页必须随之从 5,562 改成 5,545 才能与实测一致。**任何内容改动后都要重算标题页的摘要/正文字数。**
7. 拼接残渣自检：删子句后检查**括号平衡**、`..`、`;)`。本 session 丢过一个右括号、多过一个逗号，都是回读时抓到的。

### 分离"用户改的"与"你原本写的"
把参考版重建成**临时目录**（复制构建脚本、按夹名前缀替换 OUT），再 `difflib` 段落级对齐。本 session 由此一次性看清用户的全部改动：
- en dash → 连字符（手稿 16 段、图注 3 段、回复信多处）
- 直引号 → 弯引号
- **Unicode 上标被吃掉**：`1 × 10⁻⁴` → `1 × 10-4`、`2.9 × 10⁻⁷` → `2.9 × 10-7`
- 删除手稿末尾 Figure legends 节（8 段）
- 删除回复信的 `Title:` / `Journal:` 两行

## 2. 蓝标核对版（用户会要求"改动处标蓝方便核对"）

**用源头标记法，不要事后 word-diff。**

- 定义私有区字符 `O="\ue000"`、`C="\ue001"`；构建时把新增文字包成 `O + txt + C`；
- 收尾跑 `apply_blue_marks(doc)`：按标记切 run、把奇数段染 `RGBColor(0,0,255)`、删掉标记字符；
- 整段新增/整段替换的段落直接在 `set_text(..., blue=True)` / `clone_after(..., blue=True)` 里染色。

**为什么不用 difflib 事后标蓝**（本 session 试过并放弃）：
- `[1]`→上标 `1` 的编辑器格式转换被当成"内容改动"，参考文献列表 54 条全被标蓝；
- `Paragraph.text` 含 hyperlink 文本而 `Paragraph.runs` 不含 → 字符位置漂移，diff 完全错位；
- 引用密集段落里相邻词也被误标。

**必须同时产出干净版**（蓝标版不能投稿）：加 `NO_BLUE` 环境变量开关，输出到 `投稿用_去蓝标版本/`，并**核对两版文本逐字相同、0 处残留标记字符**。

**全局格式转换不标蓝**（`[1]`→上标、`[1]`→`1.`）：版面上已可辨识，逐处标蓝会淹没真正的内容改动。这条要写进给用户的说明里，否则他会以为你漏标。

## 3. 跨文档一致性审计清单

正文 ↔ 补充表 ↔ 补充图 ↔ 回复信 ↔ 标题页，逐项对：

1. **正文引用的每个补充项必须真的含那个数。** 反例：正文写 "per log-unit increase in stiffness (β=-0.061; 95% CI -0.107 to -0.014; P=0.014; Supplementary Fig. S8C and Supplementary Table S2)"，但 Table S2 与 Fig S8C **都只有两个阈值模型** → 审稿人按图索骥查不到。
   最小修法：**删掉正文那半句，把图表引用移到前一个子句**（不必新增分析，也就不会引入新数字）。
2. **主结果 β 与 95% CI 必须与补充表逐字一致。** 反例：正文（作者原文）`-0.133 (95% CI -0.173 to -0.093)`，我生成的 Table S1 `-0.133 (-0.170, -0.096)`——β 同、CI 差 0.003。
   **以作者原稿数值为准去改表**，绝不改正文（改正文＝自爆作者原文）。
3. **区间类数值（FDR、HR、范围）必须等于表里的实际极值。** 反例：正文/回复信写 `FDR 0.0012–0.011`，Table S3 实际 `0.00034–0.005`。
4. **标题页字数 = 文档实测同口径字数**（摘要＝四个结构段落空白分词；正文＝Introduction→References）。内容一改就重算。
5. 补充图的显著性标记要与补充表自洽（S6 的 `***/*/ns` 计数 = Table S3 的显著基因数）。
6. 若手稿里的 Figure legends 节被删掉，正图图注只存在于独立图注文件 → **提交清单必须包含它**（选 Figure Legends 栏位）。
7. 抓"用户清理"留下的破坏：搜 `10[-–]\d` 与 `[⁰¹²³⁴⁵⁶⁷⁸⁹⁻]`；后者计数归零 = 全部上标已被吃掉，逐个还原成 `10⁻⁴` 这类。

**报告格式（用户要求"只检查不改"时）**：逐项编号 → 每条给"最小改法"表 → 末尾问"要我代改哪几项？说编号就行"。用户会回 `2、3、4、5` 这种编号选择。**报告里不夹带已完成的修改，也不顺手修别的。**

## 4. 补充图 QA：用 PDF 文字层，别靠 OCR

- `fitz.open(pdf)[0].get_text("dict")` 抽 span（text + bbox + size）。**比 Tesseract 可靠得多**（小字 OCR 在本 session 完全不可用）。
- **子图标签位置**：先量**用户原图**的字母坐标（`re.fullmatch(r"[A-J]", span.text)`），再对照自己生成的图。
  本 session 实测用户原图风格 = 每个子图**左上外侧**（ArialMT 24pt 未加粗、第一列 x≈2% 页宽、第二列 x≈50%，y 在页面最顶）。
- 用户口述可能与自己的参考图冲突：本 session 用户先说"移到右上方"，随后更正为"左上方外侧"。
  **处理方式：按用户明确指令做，同时在回复里主动指出"你的原图其实是左上，我按你说的放在了右上——要跟原图一致就说一声"。** 他随后更正了，一次到位。
- 标签置外的确定性实现：`labs(title = lab) + theme(plot.title.position = "plot", plot.title = element_text(hjust = 0/1))`——不依赖 patchwork 的 tag 定位，可回读验证。
- **截断检测**：数值列被面板右边界切掉时 span 会以半个数字结尾（如 `-0.133 (-0.170, -0.09`）。逐 span 扫 + 断言"估计值列右端 < P 值列左端"。
- **重叠检测**：注释文字与图例/组标签的 bbox 不得相交；放不下就把 P 值挪到**单独一行**并扩大 y 上限。
- **统计量放不下就别硬塞**：半宽面板塞不下 `β (95% CI)` + `P` 两列时，改成只放 `β` 与 `P`（CI 由误差线表达、精确值进补充表），并在图注里写明这一点。

## 5. ggplot 补图的真 bug（本 session 全部命中）

- **非语法列名会吃掉配色**：`data.frame(gene=…, \`>0.40\`=…, \`>0.70\`=…)` 被 R 改名成 `X.0.40`，`pivot_longer` 后 `scale_fill_manual(values=setNames(…, c(">0.40",">0.70")))` 的 name 对不上 → **两组渲染成同一颜色且图例整个消失**（用户一眼就看出"不同分组颜色应该不同"）。
  修法：**显式构造长表** `data.frame(gene=rep(hk,2), thr=factor(rep(lv, each=length(hk)), levels=lv), deg=c(d4,d7))`。
- **小分层会让计算变 NA，标注整段消失**：某年龄层 n=1 → `head_room` 为 NA → P 值标注全没。加 `filter(每组 n>=10)` 并在图注写明"每组不足 10 人的层未显示"。
- **配色是否真生效要按像素验**：渲染 PNG 后 `collections.Counter(im.getdata())`，确认两种填充色都实际出现（如 `rgb(172,172,172)` 与 `rgb(59,84,135)`）——比"看图"可靠。
- `geom_errorbarh()` 在 ggplot2 4.x 已弃用（只是 warning，不阻断）。
