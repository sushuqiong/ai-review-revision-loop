# 数值/文本定点修改的安全规程（多轮返修的最大杀手）

> 本文件来自 v17–v19 轮的真实事故。**每一轮"批量程序化编辑"都引入了比它修掉的更多的错**。
> 用户原话：\"**务必严谨，不要引入新错误**\"。以下 6 条是踩出来的，改稿前先读。

---

## 一、绝不做"全局数字替换" —— 同一个数字常有两个含义

**事故**：把 L 周期分析样本由 2,056 统一为 2,092 时，用了全局 `"2,056" -> "2,092"`。
结果把**判别样本**（本应 **2,056 (232 dx)**，腰围完整子集）也改成了 2,092，
而 2,092 是**关联样本**（236 dx）。

```
关联样本   : 2,092 人 / 236 例   ← 主模型口径
判别样本   : 2,056 人 / 232 例   ← 腰围完整子集（做 LAP 判别必需）
```
一次全局替换让这两个口径在全稿 20+ 处混用，**修了又回退、回退又复发，跨了三轮**。

**规程**
1. 替换前先 **`grep -c` 该数字，并逐条打印上下文**，把出现位置分成"含义种类"。
2. 一个数字有 ≥2 种含义时，**只能用语境锚定的长模式**（连同前后 20–40 字符），
   或**按段落序号逐段替换**，禁止 `str.replace` 全局。
3. 替换后**反向 grep**：确认旧值在新语境下确实为 0，且新值只在预期的语境出现。
4. 数值统一后，**跨文件复扫**（主稿 / 补充材料 / Cover letter / Figure legends /
   Title page 五处同一数字），五处必须同源。

---

## 二、"改了一半"= 同段自相矛盾，比不改更糟

**事故**：修 §3.6 的 `1.018/1.020` → `1.012/1.014` 时，我的 `old_string` 只覆盖了
句子的**前半个分句**，同一段落后半句仍留着 `(pooled fit 1.020 versus 0.990)`。
结果段落变成"给出 1.014 …… 即表中报告的 1.012/1.014 …… （合并拟合 1.020 vs 0.990）"
—— **同一段三个互斥的数**。审查者一眼抓到。

**规程**
1. 补丁的 `old_string` 必须覆盖**包含该数值的完整分句**，宁可长。
2. 补丁后**重读整段**（不是只 diff），并 `grep` 全稿该旧值：在**该主题范围内**必须为 0。
3. 若一个数来自**变体模型**（不同协变量参数化 / 不同子样本），
   **连它一起删掉或明确标注出处**，不要与主口径并列——否则迟早自相矛盾。
   *本轮真凶*：`1.018/1.020、0.991/0.990` 来自"数值 PIR"变体，而 Table 6 主口径是
   `1.012/1.014`（权威源 `v17_pooled_and_T7.txt`）。同一张表只能有一个出处。*

## 三、绝不用"第一个句号"定位插入点 —— 会插进小数点里

**事故**：给句子补引用时按"第一个 period 之后插入"，而那个 period 是**小数 `0.826` 的点**：
```
错误:  the M4 per-SD OR was 0 (Table S11).826 (0.688–0.991; P=0.041)
正确:  the M4 per-SD OR was 0.826 (0.688–0.991; P=0.041) (Table S11)
```

**规程**：插入引用/文字一律**锚定一段唯一的长短语**（锚在句末词上），
或用正则 `r"\.\s+[A-Z]"`（句号+空格+大写）判句末。**永远不要 `text.find(".")`**。
改完 grep `\(Table S\d+\)\.[0-9]` 之类的"引用插进数字"签名，必须为 0。

---

## 四、交付后**绝不重跑构建脚本** —— 一次覆盖丢掉一整轮工作

**事故**：为核对词数运行了 `_build_docx_v18.py`，但 `_ms_content_v18.py` 是
**打包前的旧内容模块** → 生成的 docx 覆盖了交付稿：Table 8 回到主稿、
摘要从 278 词涨回 342 词，**整轮 BMC 打包工作蒸发**。

**规程**
1. **交付后再改稿，只在用户当前那份 docx 上做 run 级 patch**，不碰构建脚本。
2. 若确实必须重建：先确认内容模块与交付稿**同源**（抽取一次再比段落/表格），
   否则一律走四步：**恢复 `_bak/` 前态 → 跑打包脚本 → 重做后置定点修改 → 终验**。
3. 每次跑构建前 **`cp` 一份 `_bak/<name>_pre_<step>.docx`**。
4. README 里写明\"**⚠️ 不要运行 `_build_*.py`（内容模块已过期）**\"，
   并列出重建顺序，避免未来的自己/子代理再踩。

**恢复路径（已验证可用）**：`_bak/<ver>_pre_<stage>/` 存有分阶段 docx →
拷回 5 份 → 重跑打包脚本（幂等）→ 重做引用归位 → 终验 0 未通过。

---

## 五、只改用户点名的那一个东西 —— 不要顺手重排别的

**事故**：用户只指出 **FigureS2-A** 的数字显示不全，我顺手把 **Panel B** 也重排了
（面板加高 1.175→1.90 in、组距/柱宽/标签行距全改、删掉底部基线）。
用户回复：\"**还把 FigureS2-B 改得比之前难看了**\" —— 最终全部回退。

**规程**
1. 用户点名 A，就**只动 A**；B 必须给出\"**未改动证明**\"（几何偏差 0.000000 in
   或像素级 diff）。
2. 确实必须动 B 时，**先问一句**，或把改动**约束在保持原观感的范围内**
   （只加必要净空，不改高度/基线/图例位置这类"看得见"的属性）。
3. 反过来：**为了修 A 而把 B 当"顺带优化"是不可接受的**——用户的审美评价是硬约束。

## 六、看不懂的视觉缺陷：**一次未复现就请用户截图**

用户描述\"白色的几百的数字、显示不全\"，我连续**两轮盲改未中**，
最后靠用户逐字报出 `223/194/365/92/79/60/52/42` 才定位。
**正确工序：第一次诊断未能复现 → 立即请用户截图**（截图后用同一套坐标/OCR 流程定位）。

> 请用户截图不是示弱，是省两轮返工的正确工序。本用户明确接受截图报错
> （\"让他截图报错（可用 OCR 读）\"）。

## 六·补 术语与检验口径必须互推 —— "3 knots" ≠ "3 个非线性自由度"

**事故（GPT6 v18 首要意见）**：方法/表注写 \"restricted cubic spline with **3 knots**\"，
但非线性检验报的是 **3 个非线性 df**、样条模型 rank 比线性模型高 3。
审稿人据此判定\"代码可能用了 5 个结点，或把内结点写成总结点\"——**实质是术语口径不一致**。

### 事实（务必背下来）
| 记法 | 含义 | 基列数 | 非线性 df |
|---|---|---|---|
| `ns(z, knots = q10,q50,q90)` | 指定的是**内结点** = 3 个 | **4**（1 线性 + 3 非线性）| **3** |
| `ns(z, df = 3)` | 基列总数 = 3 | 3（1 线性 + 2 非线性）| 2 |
| Hmisc `rcs(x, nk = 5)` | `nk` = **总结点数**（含 2 个边界）| — | **nk − 2 = 3** |

⇒ **3 个内结点 = 5 个总结点 → 3 个非线性 df**。三者自洽。
写成 \"3 knots\" 时，按惯例只有 **1 个**非线性 df，与报出的 3 冲突。

### 规程
1. 报告样条规格时写全：**\"three interior knots at the 10th, 50th and 90th percentiles
   (five knots in total including the two boundary knots), giving three non-linear
   degrees of freedom\"** —— 不要只写 \"3 knots\"。
2. **落盘诊断**：跑一遍输出**实际内结点值、基列数、模型 rank、被检系数、分子/分母 df**，
   存成一份表（本轮 `01_数据/v18_spline_diag.*` 与 Table S10 Panel B），
   让\"术语 ↔ 检验\"可被逐位核对。
3. 自由度断言要与模型自洽：`rank` 与设计自由度的关系要显式说明
   （本轮 L 层 degf=15 而 RCS 模型 rank=18 → 默认残差 df = −2 → 检验不可估计；
   **唯一可估计设置是显式 `df = degf(design)`**，须在正文如实写明，
   且**任何无法复现的旧 P 值一律删除**，不要保留来源不明的数字）。
4. 报告 P 值前先确认它**能被当前冻结代码复现**；复现不出就写\"不可估计\"，不要沿用下游抄来的值。

> 同类：不同**协变量参数化**（PIR 连续 vs 分类、race 4 vs 5 类）会给出不同的合并估计
> （本轮 `1.012/1.014` vs `1.018/1.020`）。一张表只能有一个出处，变体值要么删、要么标注为敏感性。

```bash
# 1) 旧值残留（在正确的范围内必须为 0）
grep -c "<旧数字>" main.docx.txt
# 2) "引用插进数字"签名
grep -nE '\(Table S[0-9]+\)\.[0-9]' main.docx.txt      # 必须 0
# 3) 数字三方一致：主稿 / 补充材料 / 图表 / 投稿包
# 4) 交付前 cp 备份；确认没有跑过任何 _build_*.py
# 5) 用户点名外的元素：给"未改动证明"
```
