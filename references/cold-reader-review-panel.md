# 冷读审稿团：三名互不知情的 subagent 做对抗性审查

> 来源：2026-09 EGFR v13。用户要求"再送第三方再审一轮（这轮意见已闭环，但连轮审都还能抓到东西）"。
> 实测收益：三名 **全新上下文、不知道项目历史** 的审稿人，报出 25+ 条带证据的问题，其中 **6 条 Blocker**——
> 包括作者本人连续多轮自查都没发现的"取中位数不排序"错误和"交付示例跑不起来"。

## 1. 为什么有效
- 自审会被自己的假设固化：写生成器的人不会怀疑自己的取值方式；冷读只看**产物**，一眼看出 `0.15` 与随包表 `0.33` 的矛盾。
- 冷读者会**真的运行**交付物（跑示例、跑 `sha256sum -c`、解析 PNG/docx XML），这些是作者最容易跳过的一步。
- 三个不同视角避免同质化：编辑合规 / 生物统计 / 数据工程各看不同的失败面。

## 2. 派单模板（每个 subagent 都要写清）
- **角色与目标**：一句话定位（例："作为 Scientific Data 的资深编辑，冷读一个已完成的 Data Descriptor 投稿包"）。
- **路径清单**：正文 md/docx、表格 docx、图例 docx、图件目录、数据包目录、ZIP、以及"上一轮意见与回应"文件（让他们知道哪些已披露，避免噪声）。
- **稿件类型与硬限制**：期刊类型 + 标题/摘要字符与字数上限 + 结构要求 + 许可要求。
- **禁止事项**：只读；不改任何文件、不 git 操作、不联网写；临时文件放临时目录。
- **输出格式（强制）**：按 `Blocker / Major / Minor / Suggestion` 分组，每条 =
  【问题陈述 + 证据（文件路径/列名/具体数值/命令输出）+ 建议改法 + 能否用现有数据立即验证】；
  并**必须说明"我检查了哪些、怎么检查的"**（对判定没问题的部分同样要给核对方法，禁止"看起来没问题"）。
- **已知并已披露的局限清单**：明确列出"不要重复报告"的项（如单作者、某些数据集已排除、DOI 占位符），否则报告会被噪声淹没。
- 让每个 subagent 拿到**不同的 mandates**：①编辑/合规 ②统计/方法学 ③数据工程/可复现性（实际运行校验与示例）。

## 3. 收到报告后的**验证义务**（不可省）
subagent 的结论是**假设**，不是事实：逐条自己复现后再改。
- 本项目的三类处理：
  - **成立**：如"中位数未排序"（用脚本定位到 `x[len(x)//2]` 的根因，并解释它为何恰是某队列的值）、"校验文件自引用导致 `sha256sum -c` FAILED"、"示例 2 引用不存在的列"。
  - **部分成立/说法要改**：如"TP53=0 是数据警报" → 数据没问题，是**手稿模板按首行取值**标错了基因；处置是修生成器而不是修数据。
  - **假阳性**：如"CELLxGENE 线上核验失败"来自**第一次失败尝试**留下的旧 QC 文件；处置是用成功结果重写该文件并删除陈旧记录。
- 每条都要给出**书面处置**（`<n>_审稿意见与处置_vNN.md`）：意见 → 我的复核 → 动作 → 证据文件；未采纳/延后的写明理由。这份文档本身就是给真审稿人的答复素材。

## 4. 高频命中清单（冷读审稿人反复抓到的项，自审时优先查）
1. 期望行数 = 队列数 × 模块数？缺口行是否带"不可估计 + 原因"？
2. 每个效应行是否带**该队列的实际覆盖率**（低覆盖模块是否会被读成等价）？
3. 对照组织是否统一本体（癌旁/非炎症/健康供者/非病变）并逐队列标注、不静默合并？
4. 患者级/研究级**重复审计**与去重敏感性（"无重复 sample ID"证明不了无重复患者/研究）。
5. meta 是否报全 k / τ² / I² / 95% CI / **95% 预测区间**；公式、零方差处理、最小 k 是否写明？
6. 是否用**预设容差**表述复现（而非 "difference = 0"），并把秩一致单独标注？
7. 生存层是否有**数据字典**（终点、时间单位、删失规则、缺失处理、数据版本）？
8. 组成分数与模块分数共享基因 → 是否提供**非重叠标记集或替代方法**并限定为敏感性分析？
9. 检索流程是否给出数据库/日期/关键词/候选数/去重/排除标准（PRISMA 式计数）？
10. 是否给出**层级选用指引**（哪种分值用在哪里）、版本/变更记录、上游许可说明？
11. 图是否**真的嵌进手稿 docx**、图号与图注顺序一致、图例单独成文件？
12. 参考文献是否真实存在且正文有引用（含 27 篇队列来源文献这类"数据来源引用"）？
