来源：2026-09-30/10-01 课题2 v21→v22（GPT6 审 v21）。GPT6 的 12 条意见里**超过一半改文字解决不了**，
必须真跑分析；用户明确要求"一步步做好，不要有明显问题"。本文件记录分类判据、四类补算配方、踩过的坑。

## 0. 先分类：哪些要求必须重算

| 外审要求原话形态 | 能否只改文字 | 动作 |
|---|---|---|
| "基础模型 AUC 缺完整 CI" | ❌ | 在既有 bootstrap 里存下 base 值 → 百分位 CI |
| "配对 ΔAUC 差异未重算配对 CI" | ❌ | **同一 replicate 内**作差 |
| "ΔAUC 只是表观增量，需训练/验证" | ❌ | 时间验证 + PSU 分组 k 折 CV |
| "各层权重分别重标化，合并比较可能受影响" | ❌ | 构造**真正不同**的权重方案重跑 |
| "代数恒等式本身不是新发现，需模拟演示" | ❌ | 双场景模拟 |
| "M4 该命名为结构性模型" / 措辞过强 / 期刊不匹配 | ✅ | 定点改文字 |

**判据**：出现"缺 / 未 / 需要" + 统计名词（CI、配对、验证、敏感性）⇒ 重算；
出现"表述 / 命名 / 定位 / 匹配"⇒ 改文字。**别用改文字糊弄重算类要求**——审稿人一眼能看出。

## 1. 复用既有脚本头部，绝不重推队列

新分析脚本 = `原脚本前 N 行`（数据构建 + 全部工具函数）+ 新段。只改输出文件那一行：

```python
lines = open(SRC).read().split("\n")
head  = "\n".join(lines[:350])       # 到最后一个工具函数(如 glmAUC)结束
head  = head.replace('con <- file(file.path(OUT, "v21_matched_results.txt"), "wt", ...)',
                     'con <- file(file.path(OUTV22, "v22_x_results.txt"), "wt", ...)')
open(DST, "w").write(head + EXTRA)
```

- **先在原脚本里 grep 出关键变量定义行号**（`^LAY <-`、`^COV <-`、`^M4_MAT`、`for (nm in names(LAY))`），
  用最后一个工具函数的结束行作截取点。
- 队列定义一旦在新脚本里重新推导就会漂移 ⇒ 所有结论作废。**宁可截取，不要重写。**
- 两道门再跑全量：`Rscript -e "invisible(parse('x.R')); cat('PARSE OK')"` → 小 B（如 50）试跑看数量级。
- 耗时：B=50 × 3 层 × 5 base 约十几秒；**B=1000 的配对差版（8.4 万次 glm 拟合）要十几分钟** ⇒ 一律 background + 日志 + notify。
- ⚠️ **长作业会被 kill，别把全部补算塞进一个脚本**：本项目把 A+B 合写一个脚本跑 B=1000，
  进行到第 5 分钟被系统终止（`exit_code=-15`），A 的结果保住了但 B 全部丢失、只能重跑。
  规程：**一段一脚本**（A 一个、B 一个、C/D 一个、E 一个），各自 `saveRDS`；
  **只保留主分析需要的 base**（本题配对差只需 `A_min_mat/A_full_mat` 两个，拟合量减半）；
  被 kill 后先 `tail` 输出文件看已写到哪一行，再决定续跑还是重跑。

## 2. 基础 AUC 的 CI：bootstrap 里本来就算过，只是没存

原脚本 bootstrap 只保留 `ΔAUC = glmAUC(base+v) - glmAUC(base)`，**把 `a0` 丢掉了**。补 CI 只需带出来：

```r
ab <- vapply(seq_len(B), function(i) {
  wsz <- boot_w_raowu(d$stra, d$psu, d$w)
  a <- glmAUC(d, wsz, bn, NULL); if (is.null(a)) NA_real_ else a }, numeric(1))
ci <- quantile(ab[is.finite(ab)], c(.025, .975))
```

实测（B=1000，Rao–Wu PSU bootstrap，百分位 CI）：P base A(匹配) 0.7559 (0.7245–0.7909)。

## 3. 配对 ΔAUC 的配对 CI：必须同 replicate 内作差

跨 replicate 作差会丢掉相关性、CI 偏宽。正确做法是每个 replicate 内先算各指数 ΔAUC，再相减：

```r
pb <- vapply(seq_len(B), function(i) {
  wsz <- boot_w_raowu(d$stra, d$psu, d$w); a0 <- glmAUC(d, wsz, bn, NULL)
  g  <- glmAUC(d, wsz, bn, "glm7") - a0
  sapply(CMP_KEYS, function(v) g - (glmAUC(d, wsz, bn, v) - a0))
}, numeric(length(CMP_KEYS)))
```

**免费的自检锚点**：指数与其自身残余成分比较时该差应恒为 0。
本项目 GLM7 vs metab 的 ΔAUC 差 = **精确 0.0000 (CI 0.0000–0.0000)** ——
这既是配方正确性的验证，也是**代数恒等式的数值证明**，可在正文直接引用（比文字断言有力）。

- ⚠️ **经验 P 值的边界 bug**：`p <- 2*min(mean(dif<=0), mean(dif>=0))` 在差**恒为 0** 时
  返回 **2.000**（两个 mean 都为 1）。必须 `min(1, ...)` 夹紧，或对"恒为零"的行直接写
  "exact 0 (algebraic)"。本项目第一版输出里 bootP=2.000 就出现在 GLM7 vs metab 那行——
  **正是恒为 0 的那一行**，属于配方正确、报告口径错。

## 4. 时间验证：表观 in-sample ΔAUC 的正解

三个口径一起报最稳：

1. **跨期单向**：P 训练 → L 验证，及反向。
   用**原始 log10 尺度**，不要用层内 z 分数——否则系数不可跨层迁移。
2. **PSU 分组 k 折 CV**：折单位 `paste0(period, "_", psu)`，**必须保证每折两期都有**。
3. 报"验证集 ΔAUC"，而非层内 ΔAUC。

实测：P→L **−0.0106**，L→P **−0.0049**，5 折 CV 均值 **+0.0010**。

- **负值不是错误**。它比表观 +0.004 更有说服力（加入指数并不改善外部判别力）。
  **不要因为符号为负就换口径或删掉**；如实报告，并在正文写明"表观增量不能替代验证"。
- 坑：早期只按 psu 分折，某折剩 81 例 / 5 事件，AUC 直接 NA（base=0.4431）。
  ⇒ 折单位含 period；日志里逐折打印 `n_train/dx_train/n_valid/dx_valid`，便于识别退化折。

## 5. 权重方案敏感性：先证明方案"真的不同"

第一次实现写了三个方案（每层均值1 / 未重标化 / 人口比例），结果**三者一模一样**。两个原因：

- 脚本上游已把每层权重归一化到均值 1 ⇒ "未重标化" ≡ "每层均值1"；
- "人口比例"那版写成 `w/sum(w) * pop/tot*tot`，`/tot*tot` 自我抵消。

**诊断**：打印每层权重和 `tapply(weights(des), d$period, sum)`；相同即说明方案无差别。

**真正不同的方案**：

| 方案 | 构造 | 含义 |
|---|---|---|
| `each_mean1` | 每层归一化到均值 1 ⇒ 层权重和 = n_layer | 现状，隐含按样本量加权 |
| `equal_layer` | 每层归一化到 sum=1 ⇒ 层权重和 = 1 | 两期贡献相等（忽略样本量差异） |
| `raw` | 不做任何处理 | 原始权重 |

实测交互系数 +0.1895 / +0.1939 / +0.1895，P=0.224 / 0.213 / 0.224 ⇒ **结论稳健**，
这本身就是可报告结果（"不受权重方案影响"）。

## 6. 模拟实验：单场景必然失败，必须双场景

第一版只做"结局仅由代谢残余 metab 决定"，期望"调整后 ΔAUC 归零"→ **实测 ΔAUC=+0.142，没归零**。
原因：GLM7 = metab + log10(age) + log10(BMI)；metab 有真实效应时，调整后 GLM7 就是 metab，
增量当然不为 0。**要让"指数的表观价值消失"，必须让嵌入成分才是真驱动**：

| 场景 | 生成结局 | 实测 |
|---|---|---|
| **A 假象** | 仅由 age/BMI 决定 | 不调整 P=0.0144（"显著"）→ 调整后 **P=0.759**，ΔAUC **0.000000** |
| **B 真信号** | 仅由 metab 决定 | 调整后 GLM7 ≡ metab，ΔAUC 为正 = metab 的真实增量 |

两场景都要报，并各自附 **②`y ~ index + 嵌入项` 与 ③`y ~ 残余 + 嵌入项` 的线性预测逐点 max|差|**
（实测 3.6e-14 / 4.1e-14）——"代数恒等式"的数值证据。

模拟务必标注"**纯模拟、不含真实数据、不代表真实效应量**"（本用户对合成示例混入交付物极敏感）。

## 10. python-docx 改稿脚本的致命坑（本会话真实丢过工作）

1. **`doc.save()` 必须在任何断言/异常之前。** 本项目脚本在处理表注时抛
   `AttributeError: 'Paragraph' object has no attribute 'findall'`，而该异常发生在 `save()` 之前
   ⇒ **前面已完成的表内符号替换（6 处）全部丢失**，白做一轮。
   规程：**一个脚本只做一类替换 → 立刻 `save()` → 下一轮再校验**；或 try/except 包住易错段后仍先 save。
2. **`_Row` 和 `Paragraph` 没有 `findall`**（python-docx 公开 API 只有 `.cells` / `.text`）：
   - 行内单元格：`tr._tr.findall(qn('w:tc'))`
   - 段落内 run：`p._p.findall(qn('w:r'))`
3. **表格列名做字典查找前先归一化。** 本项目表头是 `vs METS-IR`、字典键是 `METS-IR`
   ⇒ 补 CI 静默 **0 格**。规程：去前缀再匹配，并**打印填充格数**——**0 格必须当失败处理**，
   不能当"没有需要补的"。
4. **替换文本含英文双引号会与 Python 字符串边界冲突**（`SyntaxError: invalid character '–'` 之类的
   误导性报错）⇒ 内容里的引用统一用中文引号或 `\u201c/\u201d`。
5. 报告类脚本的参数名必须与函数签名一致（`P(t, bold=True)` vs 签名 `b=`），否则中途 `TypeError` 空跑。
6. 单元格文本替换要**同时写 `w:sz` 与 `w:szCs`**（见 docx-and-figure-programmatic-qa.md）。

## 12. 结构大改被否决时：把意见转成"等效声明"（切勿假装已改）

外审常提**结构性重构**类建议（主/次分析位置互换、章节整体重排、图表重做）。**用户可能明确决定不做**
（成本高、会打乱已核对好的编号与引用体系）。此时两条捷径都不可取：

- ✗ **硬做一遍** → 结构一动，编号、交叉引用、图表顺序全要重排，极易引入新错
- ✗ **沉默不做** → 审稿人的关切无人回应，等于留了雷

**正确做法：把该条意见转化为可独立核查的声明性文字**

1. 正文新增**独立小节**，正面写明"该比较是什么、不是什么"。
   本项目例：三层比较 = **跨数据层的异质性评估，不是时间趋势证据**；直接可比的当代对比才是首要跨期检验。
2. 把**被否定的表述扫成 0**：全文 `temporal trend` / `time trend` / `over time` 等计数应为 0，
   或**仅出现在否定语境**（`rather than as evidence of a temporal trend`）。**用脚本计数，不靠肉眼。**
3. 显式**引用已存在的支撑**及其位置：方法节的预先指定层级、该层的历史敏感性定位
   （如 "NHANES III … historical sensitivity layer"）、跨层变量协调映射（各层对应变量名与定义差异）。
4. 交付说明里**如实记录"该条建议未做结构改动，改用等效声明"**及理由 —— 不要写成"已完成"。

**判据**：等效声明必须能被审稿人**独立核查** —— 去正文里找得到那段话、找得到"被否定表述计数为 0"
的证据，而不是只写在回复信里。

## 13. 用户否决结构建议时：转为「可核查的声明」，不要静默丢弃

外审常提的**结构类**建议（如"主分析只留两期、把第三期降为补充材料"）风险最高：
表号 / 图注 / 图表引用会整体位移，已核对好的数值体系容易被打乱。
本项目用户明确表态 —— 「**不做 P/L 升主分析的结构大改**」。

**不能做的**：假装已改 / 只在聊天里说"已考虑" / 悄悄删掉这条意见不留痕
（下一位 agent 或下一轮会把它当未完成待办重新提出）。

**要做的**：把该建议转化为**可在稿内核查的声明**，并留下机器判据：

1. **新增一个明确的解释小节**（本项目主稿 3.11「Interpretation of the three-layer
   comparison」）：直说该比较**不是**什么证据（"是跨数据层的异质性评估，而非时间趋势的
   证据"），并指出**哪个对比才是首要检验**（直接可比的当代 P vs L）。声明要能被读者
   当作边界条件引用，而不是含糊的免责。
2. **核查被否定表述的出现次数**：全文搜 `temporal trend` / `time trend` —— 应为 **0**
   （或**仅出现在否定句内**）。这是"声明真的生效"的机器判据，比通读可靠，
   也是回审稿人"你们是否在暗示时间趋势"时的直接证据。
3. **列举既有支撑，不要新造**：本项目核查确认 2.7 节早已把第三期定位为
   *historical sensitivity layer*、2.5 节早有跨层变量协调映射（教育 / 吸烟 / 酒精 /
   高血压的对应项）。**直接引用这些既存段落**，不要为了"显得补了东西"而重写它们。
4. **把决定与理由写进交接文档**（§12），措辞写明"**经用户决定不改结构** + 替代处理方式"。
5. 复核时**只查"该声明是否可核查、旧表述是否清零"，不要顺手重排章节** ——
   否决结构建议之后，章节编号应该保持不动（否则等于偷偷做了半个结构改动）。

**判据**：改结构只是回应意见的**一种手段**，不是唯一手段。
当风险高于收益、且用户已明确决定时，**"明确且可核查的边界声明"是等价的诚实交付** ——
它比强行改结构（打乱已核对的数值体系）更符合"不要有明显问题"的要求。
