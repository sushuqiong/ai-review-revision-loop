# 图表机器质检（OCR 版面 QA）——本用户反复投诉项的根治流程

用户原话："你画图表总是有问题。请注意 OCR 检查和完善。"（v11 轮）+（v12 轮）"确保没有低级错误"。
图表问题不是审美问题，是**可机器检出**的版面缺陷。每次出图后必须跑 `scripts/ocr_figure_qa.py`。

## 一、根因（先记住这一条，能消掉一半投诉）
**图的物理宽度必须 ≤ 6.7 in（17.0 cm）@300 dpi。** 之前 fig1 43.9 cm、fig2a 21.8 cm
→ 期刊按版宽缩放后字号跌破 7 pt，用户看到的"字太小/有问题"全部源于此。
- ggplot：`ggsave(width=6.7, ...)`，**不要**超过。
- graphviz：`dot -Gsize=6.7,9.5!`；宽图改**纵向堆叠**布局，不要靠横向拉长。
- 出图后核 `02_图片_TIFF/figure_specs.csv` 的 `cm_w ≤ 17.0`。

## 二、字号下限（印刷尺寸下成立，不是像素数）
| 元素 | 下限 | ggplot 写法 |
|---|---|---|
| 坐标轴文字 | ≥ 9 pt | `theme(axis.text=element_text(size=9))` —— theme 的 size 是 **pt** |
| 图内数值/图例 | ≥ 8 pt | `geom_text(size=3.0)` —— geom_text 的 size 是 **mm**（3.0mm≈8.5pt，2.7mm≈7.7pt 为下限） |
| 标题 | ≥ 10 pt 加粗 | `plot.title=element_text(size=11, face="bold")` |
| 行数多的条形图高度 | ≈ 0.25 in/行 + 2.4 in | 28 行 → ≈9.4 in；曾误设 0.52 in/行 → 90 cm 高，不可用 |

## 三、必须机器检出的四类缺陷（脚本判据）
1. **裁切**：OCR 文本框触到画布边缘 2 px 内 → 标题过长/边距不足（真实命中：Supp 热图标题越界）。
2. **重叠**：只统计"实质词"之间的框重叠（h≥29px 且 w≥25px 且 ≥3 个字母数字）；否则会把**网格线/误差棒端**
   误读出的 `-`/`5`/`+`/`=`（高 4–8px）当成重叠——这是最常见假阳性，必须过滤。
3. **字号过小**：报告中位框高；注意 tesseract 量的是小写 x 高度，`<7pt` 计数会虚高，**字号以代码设定为准**，
   OCR 只用于几何缺陷。
4. **关键标签缺失**：期望词表（情境名、模块名、关键数字、`n.e.`）逐个检查是否 OCR 可读。

### 三·补 裁切报错先做"墨迹判别"，否则会白改四轮
OCR 只在**文本框边界**贴边时报警，并不代表真有字被切。收工前对可疑位置做像素级复核：
```python
import numpy as np; from PIL import Image
im = Image.open(fig).convert("L"); W, H = im.size
a = np.array(im.crop((W-60, 0, W, 60)))      # 报警所在的角落
print(a.min(), float((a < 200).mean()))       # 255 / 0.0 → 纯白 = 假阳性，别再改图
```
本次实测：Fig2 连续 4 轮被报 `clipped=1`（token 为 `r`/`share`），逐次缩短标题与轴标签、加右留白**均无效**；
裁 60×60 角落发现**纯白无墨迹** → 判定假阳性收工。改图前先做这一步，可省掉 3–4 轮无效迭代。

### 三·补 2 长标题/图例是"贴边"的常见真因
- **整图标题**（`plot_annotation(title=...)`）过长会在 6.7 in 画布右缘被切：整图标题只写
  "Technical validation of the resource" 这类短句，把细节放进各面板标题。
- **图例**横排过宽同样贴边：直接 `guide="none"` 去掉图例，把配色含义写进面板标题
  （如 "D Common-gene sensitivity (red = direction disagreement; grey = not scorable)"）。
- 面板多的图按**2.2–2.4 in/面板**给高度（5 面板 ≈ 11.75 in / 29.8 cm 可接受；
  曾用 3.0 in/面板 → 38 cm，超页不可用）。

## 四、两个"标签说一套、画出来另一套"的真 bug（务必防）
- **空括号**：Fig6 渲染成 `malignant cell ()`——脚本引用了不存在的列（`sig$disease` 而 CSV 里是 `context`），
  `paste0()` 静默拼接空串。**防法**：绘图前 `stopifnot("context" %in% names(sig))`；出图后 OCR 检查
  类如 `(CRC)`/`(IBD)` 的期望 token 是否出现。
- **稳健性标记贴字**：星号/菱形 glyph 叠在热图格上会贴到 y 轴标签（OCR IoU 0.5）。
  **改法**：用 `geom_tile(data=robust_subset, fill=NA, colour="black", linewidth=1.1)` 黑框标记，
  图注改写为 "black-bordered tiles = robust"。
- **旧图复用**：Supp 图曾直接沿用上一版（v9）文件 → 数字过期。
  **铁律**：所有图都从当前冻结结果表重生成；补充图也不例外。

## 五、调用 tesseract 的正确姿势（否则静默返回 0 词）
```python
env = dict(os.environ, TESSDATA_PREFIX=r"C:\Program Files\Tesseract-OCR\tessdata")
subprocess.run([TESS, path, "stdout", "--psm", "11", "tsv"], capture_output=True, env=env)
```

- 中文/非 ASCII 路径不稳：先把图 `shutil.copy` 到 ASCII 临时目录再 OCR。
- 想看清标签，`--psm 6` 逐行输出比 `--psm 11` 更适合长标签（曾用它定位空括号 bug）。

## 六、版面习惯（减少 OCR 与读者负担）
- x 轴标签**不旋转**（`angle=0`）；用短标签或 `strwrap`/换行，不要 35° 斜排。
- 面板不要重复：`fig2a_*` 只含 A，`fig2b_*` 只含 B。
- 不可估计的格子写 `n.e.`，不留空白。
- 复杂流程/分层图优先纵向堆叠 + 明确说明"图层是并行的，不是逐层筛选"（否则审稿人会以为顺序过滤）。

## 七·补 图例与表格的交付格式（用户硬规则，**适用于后续每一次修改**）

## 九、PDF 矢量图的**文字层**质检 —— 比 OCR 精确，凡 PDF 输出优先用它

matplotlib / ggplot / Illustrator 输出的 PDF 里，文字是**真 span**，`page.get_text("dict")`
能拿到每个标签的**原文 + 精确 bbox + 字号 + 字体 + 颜色**，没有 OCR 的识别误差。
小字号（< 8 pt）OCR 会漏字串字，文字层不会。

**每次出图后跑 `scripts/qa_pdf_layout.py`（本轮新增，可直接命令行调用）**，四项判据：

| 判据 | 阈值 | 抓什么 |
|---|---|---|
| 越界 | span bbox 距页边 < 2 pt | 被画布边缘裁掉的字 |
| 重叠 | 任两 span 交集面积 > 1.5 pt² | 真·文字压文字（含同位置重复绘制） |
| 字号下限 | min(size) ≥ 9.0 pt | 缩放后不可读 |
| 期望 token | `--expect` | 关键数字/标签是否真的渲染出来了 |

- 收尾提示：`--dump` 按视觉顺序打印全部 span，**逐条和手稿对数字**（本轮 GA 16/16 命中）。
- 本轮这一个检查连抓 3 个真缺陷：S8 的 β 文本被面板右缘**截断成 `-0.133 (-0.170, -0.09`**；
  S7 面板 C 两组柱**同色且图例消失**；GA 面板副标题压住正文首行。都不是肉眼能可靠发现的。
- OCR（§一–§五）仍然保留，用于**栅格图**（PNG/TIFF）与"角落墨迹判别"。

### 九·补 本轮新增的 4 个 ggplot/R 真坑

1. **`data.frame(\`>0.40\` = x, \`>0.70\` = y)` 的列名被 `check.names` 自动改名** →
   `pivot_longer` 出来是 `X.0.40`，`scale_fill_manual(values = setNames(...))` 名字对不上 →
   **所有柱子同一个颜色、图例整个消失**，而且**不报错**（静默）。
   防法：长格式用**显式分组列**（`thr = factor(rep(c("> 0.40 (medium)", "> 0.70 (high)"), ...),
   levels = ...)`），别让列名承载分组名。出图后必须用文字层确认**图例条目文本存在**。
2. **半宽面板塞不下 forest plot + β(95% CI) + P 三列文本。** 实测 215 pt 宽的面板放完整 CI
   文本会被裁。二选一：(a) 只放 β 与 P，95% CI 由误差线表示并写进图注 + 补充表；
   (b) 把该面板改成整行宽度。放完必须回读 span 文本确认没被截断。
   间距经验值：β 列右端 → P 列左端至少留 10 pt（本轮 429.6 → 442.0 才安全）。
3. **面板字母的位置/字体/字号/颜色要从用户原图量出来，不要猜。**
   量法：取单个字母 span 的 bbox + size + font，与画布宽度一起看。
   本用户原图 = **ArialMT 24 pt、每个子图左上角"外侧"**（在绘图区之上、贴页面最左，
   第二列在 50% 处），**不是右上方**。用户口述与参考图冲突时**先问一句**再动手——
   本轮按"右上方"做完又按更正返工了一次。
   ggplot 实现：`labs(title = "A") + theme(plot.title = element_text(hjust = 0, size = 13,
   colour = "#231815"), plot.title.position = "plot")`（右对齐改 `hjust = 1`）。
4. **用户对手稿做 en dash → hyphen 全局清理后，图里的文字要跟着对齐**，
   否则同一份投稿两套写法：`2015–2018`→`2015-2018`、`Child–Pugh`→`Child-Pugh`、
   `immune–fibrotic`→`immune-fibrotic`。同理**图里引用的数字必须能在手稿里 grep 到**——
   GA 曾用了我自己复算的 `−0.169/−0.097`，而手稿是 `−0.173/−0.093`。

### 九·补 2 matplotlib 出图的 PDF：做"面板包含性"检查前先换算坐标系

matplotlib 的 y 轴**向上**，PyMuPDF 的 bbox y **向下**。用 PyMuPDF 校验 matplotlib 输出时，
面板矩形必须换算 `pdf_y0 = H - mpl_y1`、`pdf_y1 = H - mpl_y0`，否则"文本是否落在面板框内"
这条判据**完全无意义**——本轮就因此报出两条假的"越界/跨框"条目（其实是结论带的文字，
y 值恰好落进面板的 y 区间），差点去改一个没坏的东西。

- **重叠（两 span 交集面积 > 1.5 pt²）与越界（距页边 < 2 pt）不涉及面板坐标，可以直接用**——
  本轮的真缺陷（副标题压正文、数值标签压正文、S8 的 β 文本被右缘截断）都是这两条抓到的。
- 面板包含性只有在"面板框坐标也换算了"的前提下才可信；换算后本轮的结论是 25/17/19
  个文本块全部在框内。

## 十、"只去图例、留数据标注"——删图内文字时的边界判据（v19 轮真实返工）

用户说"图内上方/下方不要图例"时，**不要把数据标注一起删**。
本轮真实返工：把一个**轴内统计结论块**（`Non-linearity (RCS, M3): … dx F = 2.49, P = 0.100;
combined F = 2.18, P = 0.133`）当成"图例"删了，用户随后投诉 **"FigureS1 没有标注 p 值"**。

| 归属 | 判据 | 处置 |
|---|---|---|
| 图例键 / 整图标题 / 底部脚注段 | 位于图像**整体上方居中**，或**整体下方**以完整句子/色键形式呈现 | **删**（移入独立 Figure legends Word）|
| **数据标注** | 与曲线/点/坐标轴绑定：F/P 值、knots、参考线标签、样本量 | **保留** |
| 面板字母、面板标题 | 定位子图 | **保留** |
| 边界项（轴内图例、列内注释盒）| 在坐标区内但与某分组绑定 | **保留**，并在报告里显式列出让用户复核 |

移除后重排，并**OCR 双断言**：该删的残留=0 **且**该留的逐字命中
（本轮：Fig1 的 29 个方框与全部计数链、Fig3 的 8 个面板与 6 个面板内小注全部保留）。

## 十一、纵向裁切框架：改图高而不动数据坐标

删掉标题/脚注后会留下大片空白。**不要手调 layout 参数**，用两遍渲染：
1. pass1 按原版面渲染 → 量墨迹上下沿（`ink y = y_lo..y_hi`）
2. pass2 令 `H_new = (y_hi - y_lo) + 2*PAD`（PAD=0.07 in）、`DY = PAD - y_lo`，画布下移到 `ybot=-DY`
3. **轴区按"物理英寸"保持不变**（分数化坐标会在裁切后漂移，须显式换算并断言）

**两种几何自证（都要做）**：与旧图像素级平移比对（本轮 Fig2 重叠区 100.00% 像素 |Δ|≤2、
MAE=0.0000；Fig1 99.86%；Fig3 各子带最佳平移同为 dy=246 px → 纯平移无缩放）；
各面板矩形换算成英寸后逐位对比（本轮 8 个面板偏差 0.000000 in）。

## 十二、重叠类缺陷的栅格侧判据（PDF 文字层不可用时）

§九 的 span 交集判据需要文字层；只有栅格图时用**列投影**：
```python
ink = np.array(Image.open(png).convert("L"))[y0:y1, x0:x1] < 200
prof = ink.sum(axis=0); nz = np.where(prof > 0)[0]   # 看"最长连续段"与"≥N px 间隙个数"
```
正常刻度 = 多个窄簇 + 明显间隙；**重叠 = 一段连续长墨迹 / 间隙数为 0**。
本轮 FigureS3 实测：修复前 **794 px 连续、>20 px 间隙 0 个** → 修复后**最长 17 px、4 个 ≥15 px 间隙**。

⚠️ **最易犯的错是测错行**。本轮先测到"x 跨度 525 px、0 间隙的连续文本"，差点判定修复失败——
那行其实是**轴标题**（`Per-SD OR (95% CI), M3 (log scale)`，本来就该连续）。
**做法**：先按行墨迹量把底部切成行段，逐段 OCR 认出哪段是刻度、哪段是轴标题，**只对刻度行判定**。

## 十三、图内文字的两个高频真缺陷

1. **对数轴次刻度标签与主刻度粘连**（用户描述为"元素重叠"）→
   `ax.xaxis.set_minor_locator(NullLocator())` + `set_minor_formatter(NullFormatter())`，
   主刻度精简到 ~5 个；改完用 §十二 复测。
2. **柱上标签字号过小 / 基线参差**（用户描述为"数字显示不全、不清"）→
   同类标签**统一 ≥8 pt 并加粗**、**锚定同一 y**（本轮三标签原为 247/243/234，差 13 px →
   统一到 42.6346，差 0）；改完 OCR 逐个回读标签串确认未被裁也未碰撞。
   ⚠️ **若改字号后仍报"显示不全"，不要继续调字号 —— 直奔 §十六**：
   真正的原因往往是标签被画成了**白色/浅色**（在浅底上不可见），
   用坐标逐标签采样 5 分钟即可确认（`scripts/figure_label_color_probe.py`）。

## 十四、改图高后必须同步 docx 的 extent

docx 里 `wp:extent` / `a:ext` 是**独立记录**的。只换 media 字节而不改 `cy`，
Word 会**纵向拉伸**图片（`cx` 不变）。
```python
CX = 5400000                            # 5.906 in，保持不变
cy = int(round(CX * new_h / new_w))     # 按新 PNG 宽高比
# 按 r:embed 出现顺序逐张定位第 idx 个 cx=CX 的 extent，只改它的 cy
```
- **不要**用 `count=0` 的全局替换（多图会互相覆盖）；逐张定位。
- 改完断言 `cy/cx == 新 PNG 的 h/w`，并 md5 回读 media 与源 PNG 逐位一致。

## 十五、整块面板的标签碰撞：用"最长连续墨迹块"定量，元凶常是全宽基线

§十二 的列投影是**逐行**判据（抓单行内刻度粘连）。**整块数据区**的标签互相压叠时，
逐行看每行都"正常"，必须改用**全块连通域**判据。

### 症状识别
- 用户描述为"**数字显示不全 / 不清**"，且会**主动排除**那些其实正常的标签。
  本轮原话："不是 (n=2,494)/(n=1,796)/(n=5,408)，是几个白色的几百的数字"。
  ⇒ **不要只盯用户点名的标签，对整块面板做连通域测量**，才能找到真正碰撞的那一块。
- **OCR 侧签名**：同一面板的 OCR 输出**散落成许多行碎片**——
  本轮 Panel B 读出 `S | ml Surgery history only (n=223) } 494)` / `of n=` /
  `28 25% eo 26% a` / `© (n=79) 1.7% —— (n=60) 1.2% '` → 即标签在互相压叠。
  （碎片化 = 碰撞；逐行完整 = 正常。）

### 定量判据（面板数据区整体，标题行以下、x 轴标签行以上）
**直接跑 `scripts/figure_block_collision_check.py`（本轮回新增，可命令行调用）**：
```bash
python scripts/figure_block_collision_check.py FIG.png --y0 740 --y1 1120 \
       --expect 223 194 365 92 79 60 52 42          # 连通域 + 逐标签 OCR 回读
python scripts/figure_block_collision_check.py FIG.png --invert           # 浅色/白字
python scripts/figure_block_collision_check.py FIG.png --base 217,227,240 # 柱内低对比度标签
```
手工实现等价于：
```python
ink = lum < 235                     # 或按背景色偏离度二值化
runs_per_rowseg = [...]             # 逐行段取列投影，再算该段内"最长连续墨迹列段"
mx = max(runs_per_rowseg)           # 面板最大连续墨迹块宽度
```
| 结果 | 判定 |
|---|---|
| 任一块 > **350 px** | **碰撞**（本轮修前 1914 px）|
| 最大块 < 350 px 且各块可分离 | **通过**（本轮修后 169 px）|

### ★ 元凶通常是"全宽基线 / 坐标轴线"
本轮 1914 px 连续块的**唯一来源就是面板底部的全宽基线**（它自身即 1879 px 连续墨迹），
把柱、标签、刻度**串成一整块**。
⇒ **先查有没有横贯整宽的长直线**；它是"最大连续块"的元凶，不是标签真的挤在一起。

⚠️ **但去掉基线要谨慎 —— 用户可能明确反对**。本轮删掉基线后用户立刻投诉
"**还把 FigureS2-B 改得比之前难看了**"，最后不得不恢复。正确做法按优先级：

1. **首选：保留基线，把基线从审计口径里剔除**（基线是设计元素，不是文字）。
   ```python
   wide_row = (lum < 240).mean(axis=1) > 0.85   # 近乎全宽墨迹行 = 基线/轴脊
   keep = ~wide_row                             # 再对 m & keep[:, None] 做连通域
   ```
   本轮实测：剔除 2 个全宽行后，同一图的最大文字块 = **288/290 px → PASS**，
   文字块数 21 个（不再是 1 个糊团），基线与观感都保住了。
2. 只有用户**主动**嫌基线难看时才删。
3. 无论哪条路，重排密集柱图时**只动被投诉的那一个面板的几何**，
   另一面板必须给出"N 项几何偏差 0.000000 in"的未改动证明。

### 可直接照抄的重排参数（12 根柱 / 3 组 × 4 类的密集柱图）
| 参数 | 修前 | 修后 |
|---|---|---|
| 面板轴高 | 1.175 in | **1.90 in** |
| 组中心间距 | 1.0 | **1.40** |
| 组内柱中心偏移 | 0.30 | **0.45** |
| 柱宽 | 0.24 | **0.30** |
| 标签行距 | 1.18 | **1.42** |
| 面板内图例 | 左上（与柱争位）| 坐标区**右上空白区**（先算最高柱+标签到哪，再放）|
| 底部全宽基线 | 有 | **保留** ⚠️（不要删——见上方"去掉基线要谨慎"：删了会被投诉"改得比之前难看"；正确做法是把全宽行从审计口径里剔除）|

效果：标签横向净空 47–68 px → **74–95 px**；文字 bbox 重叠 **0 对**；字号集合 [8.0, 8.5]。
（改密集柱图层时**只动这一面板的几何**，另一面板要出"28 项几何偏差 0.000000 in"的未改动证明。）

### 收工断言（两个都要）
1. **连通域**：面板数据区最大连续块 < 350 px，并在报告里**逐块列出宽度**
2. **OCR 逐值**：每个标签（含 `(n=…)`）**逐个单独 OCR 命中**——
   本轮 9/9（223 / 194 / 365 / 92 / 79 / 60 / 52 / 42 / 89），
   且整图 `--psm 11` **一次读出全部 9 个 token**，数值逐字与数据文件一致。

⚠️ 复测时若"最大块"落在**轴内图例文字行**上（本轮 377 px），报告中要说明
**该块是图例而非柱标签**（避免误判未修好）；或顺手把图例字号降到 7.5 pt 并标记 small-note。

### 附：低对比度柱内标签的提取法（绝对阈值抓不到时）
柱内白字/浅字用 `lum < 200` 抓不到。改为**按"偏离柱体背景色"二值化**：
```python
base = np.array([217, 227, 240])            # 柱体填充色
dev  = np.abs(box.astype(int) - base).sum(axis=2)
m    = (dev > 30)                            # 文字像素
```
本轮 Panel A 的 `85.3% (n=2,494)` 用绝对阈值 OCR 只得乱码，用偏离度二值化后
`--psm 6` 直接读出完整标签。

## 十六、"标签是白色/近白" 才是最难找的一类 —— 必须按坐标逐标签采样

用户原话（连续两轮追问）：\"**FigureS2-A 还是有数字显示不全/不清 … 就是这些显示不全：
223 / 194 / 365 / 92 / 79 / 60 / 52 / 42**\"。

### 根因（脚本里的一行硬编码）
```python
axA.text(xx[i], yy, \"%.1f%%\n(n=%s)\" % (...),
         color=\"white\" if ci == 3 else \"#111111\",   # ← 第 4 类用白色
         weight=\"bold\", linespacing=1.18)
```
该类的柱段只有 **5.5 pt 高（23 px）**，却承载**两行 8.5 pt 白字** →
文字大幅溢出段外，**溢出部分 = 白字白底 = 完全不可见**，只有压在彩色段上的
一小条露出残影 ⇒ 用户看到的\"**几个白色的、几百的、显示不全的数字**\"。

**修法（三件一起做）**：① 颜色改深色 `#111111`；② 改成**单行** `\"%.1f%% (n=%s)\"`；
③ 锚点移到段**上方外侧**（`va=\"bottom\"`，`y = bottom+v+1.2`），并把 `ylim` 抬高
（108 → 114）容纳标签高度。改后 OCR 立刻读出 `8.9% (n=223)` / `7.6% (n=194)`。

### ★ 为什么我连查两轮都没找到（三个错误方法，务必避开）
| 我用过的方法 | 为什么失效 |
|---|---|
| 整图 OCR 搜 `8.9%` / `(n=223)` | **命中来自另一个面板**——Panel B 有**同名同值**的标签（且是深色正常的）。跨面板同名标签让整图 OCR 完全失去判别力 |
| 在标签附近取框，看\"最深色像素\" | 框取得太宽/太靠上时，最深色就是柱子颜色，无法区分\"没有文字\"与\"文字不是深色\" |
| 按偏离度二值化后 OCR | 白字在**白底**上偏离度为 0，根本进不了掩膜；只有压在彩段上的那一条能进 |

### 决定性诊断（照抄 `scripts/figure_label_color_probe.py`）
**先用 PDF 文字层拿到每个标签的精确坐标，再逐标签采样该坐标处的最深色。**

```python
from pypdf import PdfReader
items = []
def visitor(text, cm, tm, fd, fs):
    t = text.strip()
    if t: items.append((cm[4], cm[5], float(fs), t))   # cm 优先；cm 全 0 时回退 tm
PdfReader(pdf).pages[0].extract_text(visitor_text=visitor)
# PDF pt -> PNG px
S  = png_W / pdf_W_pt
px = round(x_pt * S);  py = round((pdf_H_pt - y_pt) * S)
box = arr[py-14:py+10, px-4:px+120]
darkest = box.reshape(-1,3)[box.reshape(-1,3).mean(axis=1).argmin()]
```
| 采样到的最深色 | 判定 |
|---|---|
| 接近 `(17,17,17)` / `(0,0,0)` | 深色文字，**可见** |
| 就是**柱体的填充色**（如红 `(200,16,46)`、蓝 `(123,163,201)`）| **该处没有深色文字 ⇒ 标签是白/浅色 ⇒ 不可见** |

本轮实测：`85.3% (n=2,494)` → 最深色 `(17,17,17)` ✓；
`8.9% (n=223)` → `(200,16,46)` ❌；`7.6% (n=194)` → `(123,163,201)` ❌。
**这一步 5 分钟就能定位，我却绕了两轮**——**遇到\"看不清/显示不全\"先做它**。

### 白字修复后的验收（三条同时给）
1. 该标签区域的**深色像素计数从 0 → 数千**（本轮 Panel A 上部 0 → 5,563 个）
2. **逐个标签单独裁剪 OCR** 命中完整串（`8.9% (n=223)`、`7.6% (n=194)`）
3. 整图 `--psm 11` **一次读出全部 token**（本轮 12/12，含两个面板的 `2,494/1,796/5,408`）

### 升级规则（省钱省时，务必遵守）
**对\"我看不到像素\"的视觉缺陷，第一次诊断未能复现时，就停下来请用户截图**
（截图后用同一套坐标/OCR 流程定位）。本轮我连续两轮盲改未中，用户不得不用文字
把 9 个数字报给我——那是本可以一次截图解决的。请用户截图**不是示弱，是正确工序**。

## 十七、"标注该不该留"的第二档：视觉突兀/语义不明的标注应**删掉**，改由图注交代

§十 讲的是"别把数据标注当图例误删"。**反向也成立**：有些标注**真实存在、也能读清**，
但用户会判定它们**"太突兀、意义不明"**，要求从图里删掉、改由图注 + 正文文字交代。

v19 轮原话：「8.9% (n=223) 和 7.6% (n=194) 能看清，但是**太突兀了、意义不明**，
是否考虑：**不显示它们，只在 figure legends 和正文用文字简要交代**？」

| 情形 | 处置 |
|---|---|
| 标注与主曲线/主柱绑定，读者靠它读图（F/P 值、knots、参考线标签、样本量）| **留**（§十）|
| 标注只属于**很小的次类段**，位置被迫外移/抬高才放得下（视觉悬空、与主体脱离）| **删**，图注交代 |
| 用户在报告里点名"突兀 / 意义不明" | **删**，不必争辩 |

**删掉后必须做三件事**：
1. **图注补一句**：说明哪一类没标、数值去哪里找。本轮模板——
   `Panel A labels the largest category (…); the smaller positive categories (…) are not labelled
   there but are shown to scale as the stacked segments above the large category, with their exact
   weighted proportions and participant counts given for each layer in Panel B.`（56 词）
2. **先量图注词数再补**（BMC 等刊硬限 **≤300 词**）。本轮 Fig1 290 / Fig3 296 已近上限，
   故只改 Figure S2 的图注；补后须复量全部图注。
3. **三处同步、逐字一致**：主稿图注 / 独立 `Figure legends_vN.docx` / 补充材料里该图的部分。

**回读校验（两个方向都要）**：OCR 该面板区确认**旧标签串已消失**，**且未删的面板仍逐值可读**
（本轮 Panel A 已无 `8.9%`/`7.6%`，Panel B 的 9 个 n 值仍 **9/9** 命中）。

**顺带回调 `ylim`**：若曾为容纳该标签而抬高（108→114），删标签后要调回，否则顶部留白过多。
