# 多模型意见分诊 + 统计防守（资源稿/数据描述稿专用）

来源：一次 Data Descriptor 稿（v14→v16）连续两轮外部模型意见（GPT6 + 腾讯 Hy4）的处置实测。
适用：任何"AI 审稿 → 针对性修复"闭环中，收到 2 份以上外部意见时。

## 1. 不同模型抓不同类别的缺陷——不要平均，要按类别合并

实测分工（两轮一致）：

| 模型倾向 | 抓到的典型缺陷 |
|---|---|
| 记账/内部自洽型 | 规则**写反**（正文与代码方向相反）；数据集计数在多处不一致（4/5、26/27/28）；补充材料编号在四处不同；版本号漂移（正文 v15、tag v14.0、模块 v12.0）；自引用 checksum 的表述 |
| 呈现/定位型 | 编号与角标拼接导致 accession 被污染（`GSE139113`）；文献缺集体作者；缺与既有资源的定位段（recount3/ARCHS4/DEE2/Xena/Toil）；"68% 一致性"埋得太后、表述过强；图注/角标排版细节 |

**做法**：两份意见并表后，按"记账类 / 统计类 / 呈现类 / 定位类"分桶，逐条**回到数据核验**，再决定修法。
不要因为两份意见都提同一件事就认为它最重要，也不要因为只有一份提就忽略（实测：单份提出的"accession 被角标污染"是真实且最尴尬的错误）。

## 2. 核验纪律：每条意见先判"能否复现"

对每条意见产出三态之一，并在处置表里写明：

* **确认**——给出复核用的实测数字（例：正文称"整数比例 >0.90 且 max>50 视为已对数化"，实测 27 个队列 integer fraction ≤0.033、max ≤17.9、`log2_applied` 全为 FALSE → 规则句子写反，代码正确）；
* **部分确认**——拆成"事实成立但危害不同"（例：accession 与上标拼接 → 渲染可读、**复制/抽取后变成另一个编号**，因此必须改为纯列表 + 区块引用）；
* **无法复现/我方不认同**——给复核方式与数字，不做空口反驳。

高危信号（这两条几乎总是真的，且优先级最高）：
1. **某个统计定义从未被验证过**（分母、方差、合并方式只写"用了 X 方法"）；
2. **数据集计数在文内对不上**（摘要 4、方法 5、图里 5、可用性 4）。

## 3. 统计类意见的标准回应模板（四件套）

被质疑"配对与非配对混池 / 分母非标准 / 方差未证明"时，只用一段辩解是不够的，出这四样：

1. **公式与命名**：写出完整公式，并**为分母命名**（例：RMS 分母 → 估计量命名 SMDH/SMCRPH，并声明"刻意不使用样本量加权合并 SD"）。
2. **方差蒙特卡洛验证**：在 (n1,n2,Δ) 网格上模拟数千次，报告 解析/经验方差比 与 95% 覆盖；一张小表即可把"假定"升级为"已验证"（实测 15 组、4,000 次/组 → 比值 0.92–1.03、覆盖 0.94–0.95）。
3. **按设计分层报告**：联合估计仅作并列，另给"仅配对 / 仅非配对"分层估计（实测 170 状态 → 83 仅配对、64 仅非配对；且 442 条队列行中 251 条为配对，说明风险是实质的而非学术性的）。
4. **换约定的全层重算**：用经典约定（加权合并 SD 的 Hedges g；配对用 d_z·√(2(1−r))）重算整个估计层，报告 同号比例 / 中位差 / 最大差（实测 163/165 同号、中位 0.014、最大 0.49 → "结论不依赖约定"）。

附带：把"低对照数队列"做成**排除敏感性**而不是脚注。实测：去掉只有 5 个对照的队列后，全部 17 个该病种状态降为单队列、必须标 not estimable——这本身就是可写进正文的发现（"该层最不稳健"）。

## 4. 记账类意见的标准回应模板（两表一注册）

1. **唯一输入登记表**：每个输入一行——标识符与版本（含排除项！被排除的数据集若出现在任何图里，必须给 collection/dataset id、版本、细胞数、来源 DOI 与排除原因）、层级、状态、是否入估计、是否可检验、原因。
2. **对账流程表**：把各部分加得起来（实测 31 = 26 纳入 + 1 应答 + 1 外部验证 + 3 未采纳），并在**摘要/方法/Data Records/Data Availability 四处引用同一张表**。
3. **补充材料清单表**：逐项列出"内容 + 是否随主稿提交 + 是否仅仓库提供"，一举消灭 S1–S17 / S18 / S20 混用类投诉。

## 5. 修复后的回归风险（每轮必做）

* 修一处常坏另一处：实测"把主表重新内嵌"导致正文表消失、"全量短横线转换"把 DOI 内部连字符改坏。
* 规则：**每一轮修完 → 重跑整套 QA（图件像素级 + 渲染级越界/重叠 + 清单校验 + 数字 vs 数据）**；全局文本变换前先**保护标识符**（DOI/UUID/URL/accession/版本串）。
* **清单必须最后生成**：任何脚本再往包里写文件之后都要重跑清单，否则 `sha256sum -c` 会报 FAILED（实测：后写的 QA 表导致 128/129 FAILED，重建后 129/129）。

## 6. 汇报格式（本用户偏好）

* 先给"我核实后认同/不认同 + 理由 + 实测数字"，再给修法与位置；不接受"已将您的意见全部采纳"这类空话。
* 每条意见一行：`编号 | 意见 | 处置与证据 | 位置`（表格式，可被用户直接搬进 response letter）。
* 明确列出"我无法复现的意见"和"仍未闭环项"（如 DOI 占位符、需要用户肉眼判断的图件审美）。
