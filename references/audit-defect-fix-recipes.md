# 审查缺陷的修复配方（Audit-defect fix recipes）

`references/multi-lens-adversarial-review.md` 负责**发现**缺陷；本文件负责**修掉**它们。
来源：课题2 GLM7×胆石症 v14 稿包在第三轮异视角审查后暴露的 4 类实质缺陷及其实测修复路径。
每类都写「症状 → 配方 → 验证」。

---

## 1. 补充表陈旧/硬编码 → 用本版数据重算

**症状**（复算视角的判定依据，三条任一即命中）：
- 表内数值在**本版任何输出文件**里都找不到（只在旧版输出里能找到）；
- 表里的 `n` 不等于本版样本链上的**任何一个节点**（实测 meta 表写 N3 `n=5,345`，
  而样本链是 6001 / 5942 / 5918 / 5724，5,345 对不上任何一跳）；
- 同一张表不同列的 `ddf` 隐含值与声明的设计自由度不符（由 `|t|` 与 `P` 反推隐含 ddf
  = 22.2 / 12.8 / 46.0，而声明的队列 ddf 是 25 / 15 / 49）。

**配方**（跨期异质性表 = 合并交互 + 逆方差 meta）：

1. **统一"共同协变量集"**——只选三时期都可得的变量（sex、race/ethnicity 归为 4 类、
   PIR 连续）。**不要用各层自己的模型协变量集**：那正是旧表口径不一致的根源。
   race 归类要写一个 `harm()`，用 `grepl` 匹配 "White/Black/Mexican/Other" 后 `factor()`。
2. **先按层内 SD 标准化指数**（per-SD），每层用自己的 SD，再进入池化。
3. **池化设计必须给 PSU 与 strata 加期前缀**：
   `strata_u <- paste0(period, "_", stra)`、`psu_u <- paste0(period, "_", psu)`。
   不加前缀时 `svydesign(..., nest=TRUE)` 会把不同周期的同名 PSU/层错并。
4. 交互检验用 `regTermTest(fit, ~index:period)`，并**报它自己的 ddf，而不是设计的 degf**——
   实测设计 degf=89，而交互检验的 ddf 是 79（总关联框架）/ 77（M4 框架）。
5. **期特定 OR 要从同一个池化模型里取对比**，不是各自单跑：
   - 参考期：`b = coef["index"]`；
   - 其他期：`b = coef["index"] + coef["index:period<pr>"]`，
     方差用 delta method `V11 + Vkk + 2·V1k`；
   - CI 用 `exp(b ± qt(.975, ddf)·se)`。
6. **逆方差 meta**：各层用**同一**共同协变量集单独拟合 → 取 `b`、`se` →
   `Q = Σ(y − ȳ_w)²/v`（`ȳ_w` 为逆方差加权均值）、
   `I² = max(0, (Q − (k−1))/Q)`、固定效应 pooled `= exp(Σwy/Σw)`。
   再补一个 **DerSimonian–Laird 随机效应**作为敏感性对照（实测 τ²=0.0325、
   pooled 1.833 vs 固定效应 1.814，彼此印证）。
7. **留档**：把旧值/新值并排写成 `<version>_tableSX_recomputed.txt` 存进 `01_数据/`，
   并注明数据源与代码路径。**这张留档文件就是"可溯源"本身**——没有它，下一轮审查还会报同一缺陷。

**心理准备：数值会真的变。** 实测变化：交互 F 6.37→6.13、P 0.0026→0.0034；
N3 meta `n` 5,345→**5,918**（变成正好等于分析样本，缺口消失）、OR 2.335→2.234；
Q 16.79→15.76、I² 88.1%→87.3%、pooled 1.804→1.814；
M4 框架交互 P **0.0284→0.0435**。这些都是**样本口径与协变量集差异**造成，不是方法错误。
**修完必须回头确认论文的定性结论是否仍成立**（本例 M4 框架仍 <0.05，结论"仍显著但更弱"不变）；
若结论被推翻，那是发现而非事故，照实改摘要/讨论。

**同步范围**：不只改补充材料表。正文里凡是引用该表的每个数字都要改
（本例 §3.6 有两段：期特定 OR、ddf、chisq、P 值、以及 P-vs-L 的 F/ddf/P），
外加补充材料表注（写明"用本版分析样本重算"）。

## 2. 图件重制后必须重新嵌入 docx

**最易踩的坑**：docx 是在 `add_picture()` 时把**图片字节**写进包的。
把磁盘上的 PNG 换成新版**对已有 docx 毫无影响**——必须重新嵌入。

**配方**：
1. 先重制/重导出 PNG+PDF（打印尺寸见 `multi-lens-adversarial-review.md` Lens B 第 10 条）。
2. 在 docx 里**删除所有含 `a:blip` 的段落**（`x._p.getparent().remove(x._p)`）。
3. 在锚点（通常是 `References` 段）前重新插入 `[图题段, 图段]` 对，
   顺序 `Figure 1.` → `Figure 2.` → `Figure 3.`。
   `OxmlElement('w:p')` + `anchor.addprevious(el)` + `Paragraph(el, parent)`。
4. **清孤儿媒体关系**：反复删插会留下 `rId` 已不被 `document.xml` 引用的图片关系。
   判定：`used = re.findall(r'r:embed="(rId\d+)"', document.xml)`，
   凡 Type 含 `image` 而 `Id` 不在 `used` 里的关系 + 其 `word/media/...` 一律删除，
   用 `zipfile` 重写包（`shutil.move` 回原位）。
   不清的话实测主稿会带 6 条图片关系却只有 3 张被引用。
5. 验证：`a:blip` 数量 == 预期；`len([r for r in part.rels.values() if 'image' in r.reltype]) == 预期`；
   并回溯每个图段最近的上方 `Figure N.` 标签确认顺序。

**制图脚本里的一个静默 bug**：`ax.text(..., transform=None)` 会退化成
`IdentityTransform`，文字被画到错误坐标（实测导致自检误报"4.3 in 宽"的假重叠）。
要么显式给 `ax.transAxes` / blended transform，要么干脆不传该 kwarg。

## 3. 舍入一致性（主稿 ↔ 补充材料）

**症状**：同一个量在主稿与补充材料里差最后一个末位——因为一处走的是**截断**、
另一处走的是**四舍五入**。实测：源值 `1.7526004` → 主稿 `1.752`、补充 `1.753`；
`2.2496265` → `2.249` vs `2.250`；`1.6234728` → `1.624` vs `1.623`。
审稿人视角看到的是"两处互相矛盾"，比数值本身对错更伤。

**规则**：
- 统一 **round-half-up**（R 的 `round()` 是 banker's rounding，处理 .5 时要小心；
  需要时用 `floor(x*10^n + 0.5)/10^n`）。
- **凡同时出现在主稿与补充材料里的量，逐个 cross-check**；这是最高性价比的一致性检查。
- 注意 .5 边界：加权比例 `93.35%` —— **不要机械地选 half-up 的 93.4**，见下条。
- **加总约束优先于 half-up**：当这些比例属于一个**互斥四分类/分层合计应为 100%** 的集合时，
  取整必须服从加总。实测该集合为 `neither 93.35 / dx-only 1.16 / sx-only 0.63 / both 4.86`：
  - `93.4 + 1.2 + 0.6 + 4.9 = 100.1` ✗（审稿人立刻据此判定错值）
  - `93.3 + 1.2 + 0.6 + 4.9 = 100.0` ✓ → **取 93.3**
  ⇒ 规则：先算出全部分项，再挑一组能凑成 100.0 的取整；**并把该组一致性写成断言**
  （`abs(sum - 100.0) < 0.05`）。图内标注、图注、正文表格三处必须同取这一组值。
- 同理适用于百分数之外的**可加量**（各层 n 之和 = 总数、各步排除数之和 = 首末差）。
  实测：流程图里 `7,770 → 6,662` 的排除数应写 **1,108**，图中曾写 1,118 被审稿人抓出。
  ⇒ 所有排除数**由相邻保留数自动相减生成**，不要在图上手写。
- 修完回到**全库**确认旧串归零（主稿段+表格、补充段+表格），而不只是改了你看到的那一处。

## 4. 轴范围裁切（CI 被轴底截断）

**症状**：曲线/CI 带在轴边界处"贴平"——看起来像数据如此，实为被裁。
实测：RCS 图 `set_ylim(0.25, 8.0)`，而 CI 下限是 **0.0798**，整条下界被切掉。

**配方**：
1. 定稿前先算数据的真实范围：`min(lo)`、`max(hi)`（本例 OR 0.208–1.151、CI 0.080–1.869）。
2. 用**数据范围**设轴（如 `ylim(0.07, 2.40)`），再按新范围重挑刻度
   （对数轴用 0.08 / 0.15 / 0.30 / 0.60 / 1.20 / 2.40 这类等比的 1-2-5 型刻度）。
3. 断言：`ax.get_ylim()` 覆盖 `[min(lo), max(hi)]` 且两侧有余量。
4. 改完**重跑重叠/裁切/留白自检**（本例自检 `TOTAL PROBLEMS = 0`），再重新嵌入 docx（见配方 2）。

## 收尾纪律

- 每修一项，回到**同一套核验**确认真的改掉：旧串全库归零、新串出现在应当承载它的**每一组**文件里。
- 本轮修复清单写进 `06_README/README.md`（本轮修了什么 + 数值怎么变 + 结论是否受影响），
  下一轮审查先读它，避免重复报同一问题。
- 审查者给的数字都要自己复核一遍（含它声称的"文件里某表有 N 行"）。
