# 三路独立冷读协议（"闭环 ≠ 收工"）

> 适用：任何"我已修完、可以交稿了"的时刻。本用户的固定追问是「修改后的 vN 没有明显问题了吗？」「再送一轮」。
> 2026-09 数据资源稿线（EGFR 跨疾病数据资源，Scientific Data Data Descriptor）连续四轮验证：**每轮冷读都还抓得到真错**，
> 且其中一半是**自己前几轮完全没发现**的（例：生成器里"取中位数不排序"、两处数值口径不一致、log2 判据在两条路径上相反）。

## 为什么必须"独立"

同一上下文里的自查会因为"知道自己怎么写的"而漏掉同类错误；冷读者必须**不知道项目历史**、只拿到文件路径与只读权限。
不要给他们任何"我们已做过什么"的叙述——否则他们会复述你的自我评价。

## 派发方式（`delegate_task` 并行三路）

| 路 | 角色 | 关注面 | 必须实际做的事 |
|---|---|---|---|
| 1 | 期刊**编辑/合规** | 目标期刊硬性要求（标题字数、摘要词数、章节序、参考文献编号与文内引用、SI 格式、数据/代码可用性、不呈现研究结论）| 解析 md 与 docx（解压 `word/document.xml`）比对；正则查 `[\d+]` 引用标记、accession、DOI；数文件 |
| 2 | **生物统计/功能基因组** | 效应量与方差公式、合并模型、k 值分布、异质性、多重比较、缺失/零方差/异常值处理、过度声称 | 独立重算效应量并与随包值比对（差异应在 1e-15 级）；按列筛选检查 k=1 行；重算敏感性场景计数 |
| 3 | **数据工程/可复现性** | 校验链、ZIP↔目录一致性、示例能否真跑、清单/版本元数据、重复与陈旧文件、路径硬编码 | 逐文件重算 SHA-256；解压 ZIP 逐字节比对；在临时目录跑 1–2 个示例并与 `expected_output` 比对 |

每路 toolsets 给 `["file","terminal","coding"]`；明确"**只读**：不得修改文件、不得 git 操作"。

## 提示词必写条款（缺一条意见就不可用）

1. **输出语言与格式**：中文；按 Blocker / Major / Minor / Suggestion 分组；每条：`问题陈述 + 证据（文件路径/列名/具体数值/命令）+ 建议改法 + 能否立即验证`。
2. **必须提交"跑过什么"**：命令或代码片段 + 结果（复算数值、比对结论）。没有证据的意见一律不算。
3. **已知已披露项列为"不要重复报告"**（DOI 占位符、单作者无湿实验、某层被整体排除、已知局限…），否则三路会反复刷同一批噪音。
4. **要求显式列出"已复算确认无误"的部分**——这既是交叉验证，也避免下一轮重复报告。
5. **环境提示**：Windows + git-bash，中文路径在 git-bash 下易失效 → 用 `os.listdir`；给出可用的 python/R 解释器绝对路径。
6. **诚实边界**：没联网就声明"未核验线上状态"；没视觉模型就声明"未做视觉判断"。

## 高频问题类型清单（用于预检，也可作为下一轮清单）

**元数据/合规类**（最容易一次全中）
- 包内自述版本号（`00_VERSION.txt`/README/CHANGELOG）与稿件版本不一致；CHANGELOG 缺当前版本条目
- 稿件写的文件数与清单/实际不符 → **文件数一律由清单动态生成**，并说明"校验条目 = 文件数 − 自引用文件数"
- 稿件没有文内引用标记（只有 References 列表）→ 在上标编号首次出现处补；accession/版本**必须在正文可追溯**（数据资源稿尤其致命）
- 章节顺序与目标期刊大纲不符（如 References 位置、Ethics 是否放 Methods 子节）
- 陈旧版本文件与当前版本并存在同一交付目录（上传错版本风险）
- 全角标点、英美拼写混用、缩写未定义

**统计类**
- 主表里 k=1 的行看起来像"合并估计"却带 p/CI/预测区间 → 标注 "single cohort; not a pooled estimate" 并置 not applicable，且正文规则要与表一致
- 同一数据两套口径（早期版本生成的结果表仍在包里，与当前主表不一致）→ 重算或移出/标注 superseded
- 分母互相矛盾（"已分型 + 未检测" 之和 > "检测过的" 总数）→ 说明两者样本宇宙不同
- 预注册阈值与代码不一致（方法写 <3、代码用 <2）→ 以**实际实现**为准改文档
- 预测区间 k 很小时退化为 CI → 加注"k 小则无信息"

**工程/自足性类**
- 声称"代码已归档"但包里没有代码 → 直接新增 `11_code/`（把关键脚本 + `README_code.md` 一起打包）
- 随包示例硬编码作者本机路径、或假定 `dataset_package/` 子目录 → 参数化/相对路径
- 声称发布的敏感性表实际只有参考行（循环体从未执行）→ 要么真跑 leave-one-out，要么改措辞为"不适用及原因"
- 重复文件（同内容两个文件名）、已被取代的旧副本仍在包内
- 清单/溯源指向不存在的脚本名（run_order / PROVENANCE 漂移）

## 处置原则

- **能立刻验证的就地修**（改生成器或改交付稿都行；若生成器锚点反复不匹配，直接在交付稿上定点改并记录"此文本已手维护"）。
- **改动会改变数字的，先复核再改**：本轮抓到"外部示例的 log2 判据与内部管线相反"——示例结果因此可能是二次对数，
  必须**重跑后**才能引用其数字；在重跑前，正文里该数字只能定位为"复用成本示例"，不得当作验证结论。
- **未修完的必须写进处置文档的"尚未完成"节**（含原因与下一步），不要静默略过——本用户会逐条核对。
- 处置文档结构：A 已修（表格：意见 / 我的复核 / 处置）→ B 实质方法学问题 → C 尚未完成（诚实声明）→ D 三人独立复算确认无误的部分。
