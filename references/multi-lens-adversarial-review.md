# 异视角对抗审查（Multi-lens adversarial review）

当同一视角的第 2、3 轮审查开始只输出「基本通过」时，说明该视角已经饱和——**继续同视角
复检不再产生信息**。此时换**真不同的视角**，并且并行两个。下面两套 lens 是本用户项目上
实测有效的组合：它们各自抓到对方完全看不到的问题类型。

为什么必须换视角（实测对照，同一个 v14 稿包）：

| 视角 | 结论 |
|---|---|
| 资深医学期刊审稿人（第 1 轮） | 「GPT6 8 项已落实，仅剩编辑级小修」 |
| 资深医学期刊审稿人（第 2 轮，换措辞重查） | 「各文件无实质问题，具备投稿条件」 |
| **独立复算统计师（第 3 轮，异视角）** | **挖出 1 项数据完整性缺陷 + 4 项舍入矛盾** |
| **期刊生产编辑（第 3 轮，异视角）** | **挖出 3 项会被编辑部退回的硬伤** |

关键教训：审稿人视角天然聚焦「论证与结论是否站得住」，对**数字能不能被重算出来**、
**印刷出来能不能读**是盲的。

## Lens 0 — 自跑确定性复检（不派 subagent，每轮先跑这个）

派 subagent 成本高、要等；而下面这些断言**父代理自己几分钟就能跑完**，覆盖的正是
「审稿人视角天然看不见」的同一类问题。**顺序：先跑 Lens 0 清掉机器可判定的缺陷，
再派 Lens A/B/C 去看证据与论证。** 实测（v21 第 2 轮）Lens 0 独立抓出 2 项实质缺陷，
且都属于 Lens A/B 上一轮没发现的类型。

每条断言都要在**全包**上跑：主稿段+表格、补充材料段+表格、独立 `Tables/`、图 PDF 文字层。

1. **OR ↔ CI ↔ P 三者互相印证**：对每行 `OR (lo–hi)` 判 `lo < 1 < hi`，与该行 P 值
   `P > 0.05` 逐一对照；不一致即内部矛盾。（实测 12/12 一致，零矛盾即为通过。）
2. **CI 在 log 尺度对称**：`|ln(OR/lo) − ln(hi/OR)| / max(…) ≤ 5%`。
   ⚠️ 仅适用于声明为 t/Wald 的区间；bootstrap 分位数区间**本来就可以不对称**。
   分布口径的坑（survey Wald F ≠ 卡方）见 Lens A 第 4 条，别把它当成稿件缺陷。
3. **逐级排除链单调**：流程图/图注里的样本序列必须逐跳单调递减，某跳反弹 = 逻辑错。
4. **摘要 ↔ 正文 同检验同数字**：取正文每个 `primary analysis` 段落的 P/估计值，到摘要里
   找同一检验。**摘要缺主分析口径（或误用被降级的敏感性口径）= 实质错误**，
   机理与修法见 `submission-readiness-adversarial-qa.md` §3d。
5. **因果动词必须是否定用法**：`causes / cause / causal / leads to / attributable to /
   risk factor for` 逐处读上下文；横断面研究里非否定的因果表述一律要改。
   **这条要读句子，不能只 grep 计数**（实测 `causes` 1 处、`causal` 1 处，都是
   `does not establish that BMI causes…` / `precludes causal inference`，合规）。
6. **局限性关键词矩阵**：横断面设计 / 自报结局 / 未测混杂 / 多重比较 / 样本代表性 /
   手术-切除偏倚 / 因果时序 —— 每个维度至少命中一次；缺哪个就是**真缺口**。
   （注意同义写法：时序靠 "reverse causation / post-diagnosis change" 命中，
   只搜 "temporality" 会误报缺失。）
7. **占位符与构建残留清零**：`TODO / TBD / PLACEHOLDER / [Author / [insert / FIXME`
   ＋构建脚本名＋`0X_数据/` 内部路径。注意 `Grant No. [2023]1` 这类**基金编号不是引用**，
   引用完整性扫描要排除它（否则误报「引用 [2023] 无条目」）。
8. **旧口径值扫描的判据是「带标注」而非「归零」**：升版后旧值作为 function-form
   sensitivity **应当保留**；通过条件 = **每处旧值都带口径标签**。按「旧值即错」处理
   会把应保留的对照值删掉。
9. **图内文字层 ↔ 图注必须对齐** —— 见下条，必须解 PDF 文字层，不能只读图注。

### 图注 ↔ 图内实际绘制（Lens 0 最高价值发现）

**缺陷形态**：图注描述的是一个口径/样本，图上画的是**另一个**。实测（v21 Fig3）：
图注写「displays the pre-specified **LINEAR** age/BMI base models」＋
「Discrimination samples: n = 2,846 / 2,056 / 5,724」，而绘图脚本的主面板分支取的是
**matched 匹配形式的 v21 重跑值、样本为关联样本 2,885 / 2,092 / 5,918**；
线性值只出现在面板内小注里。图注把「画的是什么」说反了。同一图注还把面板小注误称为
spline 结果（实为 linear）。

**为什么难发现**：图注自洽、数字都真实存在、表格也自洽 —— 错的是**图注与图层之间的映射**。
纯文本审查看不见；只有把「图上真画了什么」提取出来比对才发现。Lens B 只查
「编号/交叉引用完备」与「表图自包含」，查不到这一层。

**检查法（可复用）**：
```python
from pypdf import PdfReader
t = " ".join((pg.extract_text() or "") for pg in PdfReader("Figures/Fig3.pdf").pages)
t = " ".join(t.split())
# ① 图内出现了哪些口径标识？应与图注描述一致
for kw in ["matched base", "linear form", "dashed overlay", "log10 age", "spline"]:
    print(kw, t.count(kw))
# ② 图内出现的样本量，逐一回到绘图脚本确认它来自哪个数据分支
# ③ 面板数 == 图注声明的面板数（本轮 8 = P/L/N3 各 2 base + N3_74 overlay 2）
```
再对着绘图脚本的取值分支核（本轮：`auc_val()` 里 `if is_overlay: 取 v13/线性
else: 取 v21/匹配`）—— **图注必须把两个分支都写清楚，并说对哪个分支对应哪几行**。
发现错述后，改图注还是改图取决于哪边是设计意图：本轮意图是「主面板 = 主分析口径」，故改图注。

**顺带一致性**：同一稿内各图是否都标了样本量（本轮 Fig1/Fig2 图内都有 `n = …`，
Fig3 没有、只写在图注里）。风格不一致不致命，但要**主动列为观察项告知用户**，
不要默默忽略，也**不要擅自重跑图**（重跑要连动重嵌 docx，风险 > 收益）。

### 引用数值必须能在**当前包**内找到（版本漂移型孤儿数字）

比「引用了不存在的表」更隐蔽的一类：数值**真实存在，但只存在于上一版的源码文件里**，
本版交付包中没有任何表/图承载它。实测：正文写「under the earlier spline specification
it was **+0.0064**」，而 Table 4 只有 matched（Panel A）＋ linear（Panel B）两个面板；
+0.0064 只存在于上一版 `v13_auc_markers.csv`。**换口径为主分析（升版）后最容易留下这种
孤儿数字**——旧口径被降为敏感性，但正文里对它的引用没跟着落到某一版产物上。

**判据**：把正文里每个独立数值 grep 一遍，确认它在**本版**的主稿表格、补充材料表格、
或图内文字层中至少出现一次。只在旧版源码里出现 ⇒ 二选一：
- 在某个产物里补上它（加面板/加行），或
- 在正文就地标注其口径与样本，使读者可追溯
  （本轮改为：三口径并列 `matched +0.0040 / linear +0.0052 / spline +0.0064`，
  并各自注明 `association sample` vs `waist-complete discrimination samples`）。

## Lens A — 独立复算统计师（replication auditor）

**人设/指令要点**：明确告知「你不是审稿人，不要审阅文字/修辞/结构，也不要重复前人意见。
你的唯一产物是『数字能否复现』的清单」。要求用 R/Python **实算**，不许目估。

### 必做核验（可直接复用）

1. **尺度换算**：`OR_common == OR_own ^ (SD_target / SD_own)`，用小数列 SD 重算，容差 1e-3。
2. **百分比加和**：每个队列的分类加权比例合计是否 100.000；未加权计数是否等于该队列 n。
3. **分母闭合**：每个结局的 有效 n / 病例 / 缺失 各是多少；四分类合计与表头差的那个人
   是谁；各阳性口径之间的差能否被「同一批状态不完整者」完全解释。
4. **OR ↔ CI ↔ P 内部自洽**：
   - 由 `log(CI)` 两端反推 SE：`se1 = (log(hi)-log(or))/t`、`se2 = (log(or)-log(lo))/t`，
     `se1 == se2` 说明**在 log 尺度上对称**（若用的是对称 CI 却不对称 → 内部矛盾）。
     实测 60+ 条全部落在 1e-6~6e-4 舍入量级 = 自洽。
   - `P` 与 SE 是否匹配。**注意分布口径**：本领域用 survey Wald F(1, ddf) 而非卡方，
     用卡方重算会得到 ≠ 的 P（实测 0.0616 卡方 vs 0.0676 F）——那是**复算方自己的方法偏差**，
     不是稿件错误，须如实标注而非报为缺陷。
5. **差值恒等式**：配对比较表里 `pair ΔAUC == ΔAUC_A − ΔAUC_B` 是否逐行成立（差值应为 0）。
6. **样本逐步排除链**：每一跳的差值是否等于该跳声明的排除原因（8 个节点差值应全为 0）。
7. **端到端重跑**：至少一条完整链路从**原始文件**（xpt/dat）重跑到最终 OR，验证中间产物
   （单位换算、重算派生物）与稿件一致。
8. **硬编码 override 审计（本轮最高价值发现）**：在制图/制表脚本里搜
   `override` / `OVERRIDE` / `hardcod` / 手工 dict 字面量。
   **实测**：`_make_supp_figs_v13.py:286` 有
   `override = {("N3","dx_nosx"): (2.506, 1.710, 3.672), ...}`，
   源 TSV/独立重跑都是 **2.518403 (1.715231–3.697668)**。这个假值一路传进了正文表格。
   规则：**投稿前对每个脚本身份的表/图数字，做一次「源码 TSV → 稿件」的批量 diff；
   发现 override 一律删除并重生成**。override 通常是上一轮为「对上某个数字」临时加的补丁，
   下一轮换数据后就成了静默错误源。
9. **未核验项要显式列出**（缺源文件、单 PSU 层导致无法重算等），不要猜测补全。

### 输出格式
逐项复算表（数字 | 稿内值 | 复算值 | 差异 | ✓/✗）→ **无法复现清单**（给位置）→
算术不自洽点 → 总体判定（可复现 / 部分存疑 / 不可复现）。

## Lens B — 期刊生产编辑 / 报告规范审计员

**人设/指令要点**：明确「不要审阅统计方法或结论；唯一视角是这份稿包能否通过编辑部初筛与
生产流程」。先声明假定的目标期刊族（BMC / BMJ Open 类：STROBE、结构式摘要 ≤350 词、
Vancouver 参考文献）。

### 必查清单

1. **表/图编号与交叉引用双向完备**：正文引用的每个 Table N / Figure N 都存在；
   存在的每个表/图都被正文引用。图嵌入顺序 == 图题序号。
2. **表/图自包含**：每个表有标题；表注能否脱离正文读懂；表内单位与缩写是否在表注定义。
3. **缩写首次使用**：正文每个缩写在首现处给全称；**图表注各自定义**（图表必须自包含）。
   实测命中：`HDL`、`PSU` 全文**任何位置**都无全称；`LDL`/`HOMA-IR`/`METS-IR`/`AUC` 只在
   参考文献题名里出现过；摘要里多个缩写未定义即用。
4. **是否为 BMC 类补了独立 `Abbreviations` 章节**（常见缺口，缩写表只存在于补充材料不算）。
5. **参考文献 Vancouver**：编号 == 正文首现序；作者著录约定一致（多数「3 作者 + et al.」，
   个别列全部作者即为不一致）；DOI/URL 齐备；无重复条目。
6. **结构式摘要**：四段齐全；Keywords 数量符合目标刊；**词数**——同时报「不含标签」与
   「含标签」两个口径，并按最严者判断（实测 346 / 350，若刊方把结构标签计入就正好压线）。
7. **声明完整性**：Ethics / Consent / Data availability / **Code availability** /
   Competing interests / Funding / CRediT / Acknowledgements / Abbreviations。
8. **作者块三处一致**：主稿 vs Title page vs Cover letter 的顺序、†/*、单位编号、邮箱；
   上标形式是否统一（主稿用纯文本 `Su 1,†` 而 Title page 用 `¹,†` = 制版不一致）。
9. **修订痕迹为零**：解 docx XML 查 `w:ins` / `w:del` / `w:moveFrom` / `commentReference`，
   并确认 `trackChanges=false`、无 comments.xml。这是二值证据，最容易自证清白。
10. **图像生产质量（本视角最高价值发现）**：
    - 分辨率 ≥300 dpi；
    - **物理尺寸 vs 版心**：`figsize` 若按英寸设成 14–18 in，而图内字号只有 11–14.5 pt，
      被期刊缩到单栏 ~3.4 in / 通栏 ~7 in 后，有效字号降到 **4–5 pt**，几乎必被生产环节退回。
      **正确做法：figsize 直接设成目标印刷尺寸（≤7.2 in 宽），字号按该画布定（正文级 ≥8 pt、
      图内小注 ≥7 pt）**；内容过密就**精简元素**（合并行、缩短标签、用缩写并在图注给全称），
      **不要放大画布**。注意 `MIN_FS=11` 之类的下限断言若建立在超大画布上，等于没约束。
    - **PDF 字体类型**：matplotlib 默认导出 **Type 3**，部分出版社 preflight 报「字体未嵌入」。
      修：脚本开头 `matplotlib.rcParams['pdf.fonttype']=42`（并 `ps.fonttype=42`）。
      验证：`zlib.decompress(pdf_bytes).count('Type3') == 0` 且 `count('FontFile2') > 0`。
    - 表必须是原生 Word 表（可编辑），不能是图片。
11. **补充材料 ↔ 主稿声明一一对应**（S-numbering 三处：主稿声明段、Title page 统计行、
    STROBE 各行的 S 引用）。
12. **排版一致性**：`P=0.048` vs `P = 0.048` 空格风格；千分位统一用逗号；en dash 用于范围、
    减号用于负值；无重复词/缺失空格；**是否有行号与页码**（送审常要求）。
13. **投稿包完整性**：6 文件齐全；Cover letter 是否指名期刊/主编；Highlights 字符数上限、
    且部分刊要求不用缩写。

### 输出格式
逐项 ✓/✗ + 位置 → **会导致编辑部退回/返回修正的硬伤**（按严重度）→ 建议 → 总体判定
（可直接投 / 需小修后投）。不确定的项要显式标为不确定（例如字号可读性取决于期刊实际版心）。

## 两套 lens 都适用的收尾纪律

- **并行派发两个任务**（一次 delegate_task 的 tasks 数组），互不重叠、各自只做自己的事。
- **审查者给的计数/结论要自己复核**。实测两位审查者都声称「Table 5 只有 12 行 × 5 = 60 个
  配对」，实测该表 14 数据行 × 5 = **70**（含 Panel A/B 与 N3 20–74 两行）。
  直接 `len(table.rows) - 1` 一数就知道——**别把自己的表格计数外包给审查者**。
- 审查发现的每一项，修复后都要回到**同一套核验**确认真的改掉了（例如 dx_nosx 改完要确认
  旧的 2.506 在**全库**（主稿段+表格、补充材料段+表格）归零，而不只是改了一处）。
- **凡父代理打算对外声明的「已核验」结论，都要在审查指令里写明「请独立重跑，勿只读结论」。**
  实测：父代理据自写校验器宣布「代码可完整重建交付稿」，独立审查者重跑后**证伪**
  （每轮多 7 个空段、且不幂等，根因见表后空段双计）。自写的校验器只覆盖自己想到的失败模式，
  **它检测不出自己的盲区**——所以关键声明的复现必须交给未参与编辑的一方。
- 同理，**给审查者的指令要包含「你可能会发现的是我本轮编辑引入的问题」**（lens C），
  并列出你自己刚做过哪些批量操作。实测 lens C 一次抓出 11 项，硬伤全部是批量编辑造成的。
