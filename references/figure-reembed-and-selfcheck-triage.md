# 换图重嵌 + 图脚本自检断言甄别 + 口径三处对齐

来源：GLM7 课题2 v21 续建（2026-09）。适用于「主稿已定稿，只需换入新版图 + 同步补充材料」这类增量交付。

## 1. DOCX 图片重嵌（换图，不重跑构建脚本、不动排版）

**触发**：用户明确指位换图，例如「重嵌主稿（Fig2→image3.png、Fig3→image4.png，**非 image2**）」。
用户会主动纠正槽位——**不要凭 media 文件序号猜**。

**步骤**

1. 解包并读关系表，拿 rId → media 映射：
   ```bash
   unzip -o -q 01_Manuscript.docx -d tmp
   ls tmp/word/media/
   cat tmp/word/_rels/document.xml.rels | tr '>' '>\n' | grep image
   ```
   实测映射：`rId11→media/image2.png`、`rId12→media/image3.png`、`rId13→media/image4.png`。

2. 用**文档顺序**确认槽位归属：`document.xml` 里 `r:embed` 出现的先后 = 图注先后（Figure 1 / 2 / 3）。
   可用 python 列出：`re.findall(r'<w:p[ >].*?</w:p>', xml, re.S)` 后筛含 `r:embed` 的段落，看前后文。

3. **换图前必须核对宽高比**：新图 `w/h` 与 XML `<wp:extent cx cy>` 的比值需一致（差 < 0.001），
   否则插图会被拉伸 → 必须同步改 `wp:extent`（EMU，1 in = 914400）。
   实测：旧/新比值 1.0075 / 1.0079、1.5073 / 1.5063、1.1198 / 1.1198 → **可直接替换，无需改 extent**。
   （顺带升级分辨率：旧 image2/image3 只有 1342×1332、1135×753，新图为 2160px 宽 300 dpi。）

4. Python `zipfile` 逐条改写（其它条目原样写回），**先 `shutil.copy2` 备份 docx**：
   遍历 `zin.infolist()`，命中 `word/media/imageN.png` 时换成新图字节。

5. 回读验证：从新 docx 里 `open` 三个 media，确认像素尺寸 = 新图尺寸。

**要点**：python-docx 没有替换已有图片的 API；走 zip 层最快，且完全不触碰 XML/排版。

## 2. 图脚本 `TOTAL PROBLEMS: N` —— 先甄别断言是否过期，≠ 图坏了

长流水线的图脚本自带自检（overlap / bounds / box-overlap / fontsize / margin / 保留-移除断言）。
一旦本轮改了设计意图，`TOTAL PROBLEMS` 会非零，**但多数是断言过期**。逐条归类：

| 类型 | 判据 | 处置 |
|---|---|---|
| 保留断言过期 | 断言的是**标签文字**（面板标题 / 轴标签），而本轮设计确实改了措辞 | 更新断言，不算缺陷 |
| 数值当文本核对 | 断言某个 ΔAUC 文本出现在 PDF 里，但该值只以**点 / 误差棒坐标**呈现 | 改断言为坐标核对，或删除 |
| 真缺陷 | 像素级重叠 / 裁切、字号 < 7 pt、margin ≤ 0、交付硬校验非零 | 必须修 |

**实测判定（v21 Fig3，TOTAL PROBLEMS = 15，全部为前两类）**：
- 11 个 = v19 旧面板标题断言（v21 已合法改标题）
- 4 个 = 把匹配口径 ΔAUC（+0.0040/+0.0011/+0.0033/+0.0017）当 PDF 文本核对——值以坐标呈现，必然 MISSING
- 反证材料（同一份日志里全部正常）：`[v21 保留断言] 面板数 = 8 (期望 8)`、`线性口径小注 = 6 格`、
  `check_overlap / check_bounds / check_box_overlap = 0`、`fontsize_audit` 全部 ≥ 7 pt、
  `交付硬校验问题: 0`、PDF 逐字核对 6/6 OK。

**报告写法**：写「图本身正确；N 个自检问题为断言过期（列出类别与数量）」，
不要笼统回「有 15 个问题」——那会让用户以为图坏了。

**脚本 bug 顺手修**：`MM, MAUC = match_auc_tables()` 之类的解包错配
（函数返回 3 值、调用处解包 2 值 → `ValueError: too many values to unpack`）改成 `MM, _LMM, MAUC = ...`；
多处调用要一起改。

## 3. 口径（analysis-sample definition）必须在 正文 / 图注 / 图内 三处对齐

同一名义亚组在不同分析分支下 **n 不同**，是最容易漏审的不一致。实测：

| 分支 | N3 20–74 y | 说明 |
|---|---|---|
| 关联样本 association | **5,290 (353 dx)** | 不需腰围 |
| 判别样本 discrimination | **5,141 (340 dx)** | 需腰围 complete-case（LAP 等比较指标） |

两者都正确，但**引用时必须配对**：
- Fig2 图注（关联估计 M3/M4）→ 5,290 / 353 dx ✅
- Fig3 图内 overlay 行（判别 ΔAUC）→ 5,141 / 340 dx ✅
- Fig3 图注若只写全年龄判别样本 `5,724 (438 dx) / 2,056 (232 dx) / 2,846 (296 dx)` 而**未单列 20–74 y 的 5,141 / 340 dx → 需补一句**。

**核对动作**：把三处列成表逐项对照——① 图脚本日志打印的「图内 n / dx」、② 图注文本、③ 正文样本量段。
不一致时先判定属于哪个分支（association vs discrimination），再决定改图注还是改图，**不要直接改数字**。

同类已知对偶（沿用同一判据）：`Panel A 用关联样本 2,885 / 2,092 / 5,918`，
`Panel B 线性敏感性沿用腰围完整的旧判别样本 2,846 / 2,056 / 5,724`。

## 4. 驱动返修的「数值对照清单」文档模式

数据目录（非交付目录）下的 `V<N>_<变更名>_数值对照与需改表述清单.md` 是高效工作台，值得复用其结构：

- **§0 运行概况**：样本量/事件数「实测 vs 期望」+ degf / PSU / 层数校验表（全部 ✓ 才继续）
- **§1–5 逐指标 旧 vs 新**：OR / ΔAUC / 交互 F，明确标注方向变化（如「CI 含 1，转为不显著」）
- **§6 需改表述清单**：**按 docx 段落序号定位**（`段 11` / `段 191` / `段 206`），每条给出「现文 / 问题 / 建议改法」
- **§7 无需改动清单**：显式列出结论稳健、不该动的地方 —— 防止返修时过度修改
- **§8 更正自己上一条消息**：把之前说错的表述改正并留痕

返修时按 §6 逐条打勾；被用户追问「还有没有别的问题」时，用 §7 + 三处口径对照表回答。

## 5. 本轮踩到的外围坑（一句话级）

- **heredoc 里写 Windows 路径会炸**：`\\U` 被当 unicode 转义（`truncated \UXXXXXXXX escape`）→
  改用 `write_file` 落一个 `.py` 再跑；路径拼接用 `chr(92)` 或原始字符串。
- **`hermes config set` 不能写 list 型键**（`custom_providers.*`）→ 直接 Python YAML 编辑（先备份）。
- **补充图脚本从旧版复制过来时，`OUT` 常指向旧版本目录**（如 `课题2v19\03_图表`）——
  运行前先 `grep -n "^OUT\|^D = \|^DATA = "` 确认数据源（保留旧版=权威）与输出目录（改到新版）分离。
