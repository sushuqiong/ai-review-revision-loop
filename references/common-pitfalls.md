# 常见陷阱（已踩坑记录）—— 完整版

> 从 SKILL.md 下沉而来（原为 20,650 字符）。SKILL.md 只保留索引。

1. **数学不可能值**：DCA 净获益不能超过患病率；校准 slope 用"重校准后概率评估"是循环论证（应为原始 OOF 概率）
2. **可复现性**：预测模型论文必须给完整公式（z 标准化常数 + 截距 + lambda），否则审稿人必问
3. **引用编号**：Vancouver 要求按正文首现顺序；subagent 重排 refs 后必须重新核对正文引用。注意：①引用可能跨 run 存储（python-docx 逐 run 替换会漏），稳妥法是整段重建文本；②文献表在表格/图注中的引用也要统计（只扫段落会误报"未引用"）；③区间写法 `[8–10]` 会吞掉中间编号，需拆分显式引用；④重排后必须做全量 token 多重集校验（防止遗漏某段未改）
4. **术语过度声称**：同源 NHANES 时间窗验证 ≠ external validation，应叫 temporal validation
5. **共享组分**：暴露与结局共享变量（如 FLI 含 BMI/TG 而 GLM7 也含）会产生数学耦合，必须讨论
6. **Cover letter 隐私**：生成时若 subagent 自动填了真实署名/邮箱，需向用户确认（可能已写错，如旧邮箱）
7. **Rscript -e 段错误**：Windows git-bash 下 Rscript -e 偶发段错误，改用脚本文件方式执行
8. **图题物理顺序**：docx 中图片段和图题段是独立段落，图号正确但物理位置可能乱（如 Fig5 在第2位），需移动段落 XML（body.remove + anchor.addnext）
9. **GitHub 发布隐私**：技能 repo 发布前必须扫描（grep 用户名/邮箱/院校/路径），用 noreply 邮箱提交
10. **不要信任视觉模型对图表美观的判定**：vision_analyze 对"是否难看/是否重叠/字号是否小"几乎总回答"清晰专业"，与用户实际感受严重不符（本会话用户明确说图"太难看了"而视觉模型三次都说没问题）。判断图表质量必须用**客观可测标准**：SVG 字号文本 ≥12pt、用 systemfonts/strwidth 实测文字不溢出、森林图文本列用 coord_cartesian(clip="off") 移出绘图区防与 CI 重叠、patchwork 合并 DCA 图时子图必须保留 legend 供 guides="collect"（否则图例整体丢失）、xlim 要容纳长 CI（如 OR=52.2 需 x 上限 ~900）。详见 references/figures-lancet-fixes.md
11. **中介路径图系数必须取调整后模型**：mediation 包的 a 路径是 `lm(GLM7 ~ DII + 协变量)`，裸未调整回归的 a 可能≈0 甚至符号相反（本会话实测 -0.0008 vs 调整后 0.022***），图会画错方向/显著性。从与 mediate() 相同的模型取 coef + 动态星号
12. **校准图禁用 coord_equal**：它强制等比例压缩绘图区，14pt 标题被推出画布（用户反馈"标题没显示全"）。改 coord_cartesian + 加大 plot.margin；χ²/→ 等特殊字符在 sans 字体触发 mbcsToSbcs 失败，用 "Chi2"/"->" 替代
13. **多行注释/长 CI 的处理**：两条 P for trend 同坐标必重叠 → 加 yy 列分开放置；一组误差棒 CI 过宽无法显示时加 plot.caption 脚注诚实说明（不要静默省略）；ROC 所有曲线都要给 DeLong 95%CI（用户问"为什么有的没有"）
14. **改短图表文本必须同步改宽度计算**：森林图标签从 "(n, events)" 缩短为 "(n)" 时，txtw()/left_w_in 的格式化字符串要同步，否则文本与 CI 区间错位
15. **docx 图题顺序调整**：图题物理顺序 ≠ 编号顺序时，用 python-docx XML 元素移动（body.remove + addnext）重排图块，见 references/journal-submission-format.md
16. **Word 优先交付**：用户偏好 .docx 而非 .md（论文/报告/交付清单一律 Word）；Cover letter 也要 docx+pdf 双份
17. **图表修复记录落盘**：每轮图表修复后把"用户反馈→修复内容"写进 `06_审稿与修改/图表修复记录.md`（三课题各一份），便于追溯和用户复查
18. **docx 表格 XML 可能悄悄损坏**：python-docx 重建表格或 vMerge 合并单元格时，常见症状：表头重复两行、P interaction 数值整体错位一行（读者看到的交互 P 值全错）、多个标签堆叠在一个合并单元格而数值分散多行无法对应。审计必须用 lxml 解析 docx 表格 XML 检查 vMerge/重复表头/单元格内容对应，不能只看渲染文本。重建时用原表格式最完整的单元格深拷贝（保字体/字号/上标）
19. **数值不能跨来源混用**：同一指标（如 DCA 净获益）若来自两个脚本的两种公式（tp/npos−fp/nneg×w 非标准 vs tp/n−fp/n×w 标准 Vickers），数值会差约 2 倍且非标准值可能超理论上限（NAFLD 患病率 0.504 却报 NB 0.707）。审计时对每个关键指标确认全论文只有一个来源/一种定义，否则统一重算
20. **systemfonts 函数名坑**：`string_widths`（复数）在 systemfonts 1.3.2 不存在，正确是 `string_width`（单数，返回 pt）。用错函数会让"精确测宽"静默走兜底估算 → 森林图文本边距算不准 → 文字被裁/重叠。症状是图"好像没问题但总有文字越界"
21. **ggrepel × scale_x_reverse 不兼容**：ggrepel 0.9.8 在 `scale_x_reverse` + xlim 下会把标签渲染到画布外，只留下灰色引线（用户看到"无意义水平虚线"）。绕开方案：用 `-log(λ)` 作 x 轴（λ.min 自然在右、普通轴 ggrepel 正常）+ `segment.color=NA` 去引线
22. **审计产出也要落盘**：三篇论文的投稿前审计报告（高/中/低问题清单）保存到 `06_审稿与修改/投稿前审计/`，已修复项标注 ✅，未修复项（如占位符需用户填）留给用户
23. **图表文件名必须对齐论文图编号（系统性错位是\"图看不懂\"的头号陷阱）**：本会话 `04_图表_矢量/` 的文件名（Figure2_density/3_ROC/4_RCS/6_DCA/7_calibration/8_LASSO）与论文正文图编号体系（Fig2=系数剖面+LASSO path、Fig3=RCS、Fig4=ROC、Fig6=25折AUC、Fig7=DCA、Fig8=校准、Fig9=外部验证）**整体错位一位以上**，用户看到\"Figure 8 LASSO 曲线重叠、要不要删\"时真相是：LASSO path 是正文 **Figure 2B**（重要图），根本不是 Figure 8；Figure 8 是校准图。处理流程：①从 docx 提取全部图题（`Figure N.`）与正文 Figure 引用顺序 ②列文件清单对照，重命名对齐 ③补缺失图（Fig2A 系数剖面、Fig9 外部验证 ROC 可能从未生成）④删错位旧文件。另外：**拆分图时用顺序编号而非 A/B 后缀**（用户建议 Fig3A/3B → Figure 3/Figure 4，后图顺延），且必须同步三处：文件重命名、图内 `labs(title=...)`、docx 正文引用与标题页 \"Figures: N\" 计数——只改一处必然再被用户抓
24. **haven_labelled 列静默破坏 table()/glm()**：CHARLS（H_CHARLS_D 等 SAS 导出）的疾病列是 haven_labelled 类型，`table()` 直接报错、`glm()` 可能静默失败 → 图里 Q1 有数据 Q2-Q4 全空（本会话 Fig6 CHARLS 图 Q2-Q4 无值，用户问\"验证没意义吗\"）。修法：`as.numeric()` 转换后使用（数据框通常已有转换好的 numeric 列如 `digest`，优先用它）；诊断时先 `class(d$col)` 再 `table()`，不要假设列是 plain numeric
25. **折间比较必须用配对检验**：25 折 CV 的 GMS vs GLM7 AUC 比较，审稿人/用户会问\"是配对 t 检验吗\"——同一折内的两个模型 AUC 天然配对，必须 `t.test(auc_gms, auc_glm7, paired=TRUE)` 并把 t/P 标在副标题；配 `geom_line(group=Fold)` 配对连线展示。不配对的检验会被判方法学错误
26. **参考类别标签不要显示无意义区间**：四分位图 Q1（参考组）显示 \"1.00 (1.00–1.00)\" 是噪音，标 \"1.00 (ref)\" 即可；用户会问\"Q1 的数值和范围是 1.00 吗\"
27. **图表数值必须与论文数值单一来源**：DCA 图重画后必须用脚本核验图内数值 == 论文正文数值（本会话重画 DCA 后独立重算 NB@0.30=0.358 vs 论文 0.357，确认一致才放行）；任何图改版后都跑一遍数值比对，防止"图是新值、文是旧值"
28. **论文数值修正后必须同步所有衍生投稿材料**：手稿升版（如 v3→v5 修正 OR/样本量）后，Cover letter、Highlights、Graphical Abstract 说明、Title page 里的同一数值常仍是旧值（本会话 Cover letter 还写着 1.045-1.057 / 6.6-25.7 / "External Validation"，而 v5 已改 1.041-1.057 / 6.8-33.0 / "Exploratory Assessment"）。修完 docx 后：grep 所有衍生文件里的关键数字（OR 范围、AUC、术语），逐文件替换并重新转 PDF；术语变更（external→temporal/exploratory）同样要同步
29. **git-bash 无 zip 命令**：打包 Figures.zip 时 `zip` 在 MSYS bash 不存在（command not found），用 Python `zipfile.ZipFile` 一次性打包全部 SVG/PDF/PNG（注意脚本里 cd 子目录的相对路径问题，直接用绝对路径 out + 相对 basename）
30. **手稿已声明但图注缺失**：标题页写 "Figures: N" 但正文只嵌入部分图时，审计会发现"有图文件/图号声明、无图注无正文引用"（本会话课题1 声明 Figures: 6 但正文只有 1/2/3 图注）。修复：补全缺失图注段（插到 References 前，italic 10pt）并补正文引用，或删图改计数——两个方案都要写进缺项文档让作者确认

31. **验证 AI 意见中的数据指控再传播**：AI 审稿意见声称的算术/统计矛盾必须先对原始数据文件核实（JSONL/XLSX），属实才写进新版；本会话 110≠100 属实（正文文字错、数据对）、v21 kappa 与 v22.1 矛盾也属实。引用核对脚本注意 en-dash：`[1–6]` 不会被 `[0-9,\-\s]+` 正则匹配（\u2013），要显式处理再断言"无孤儿引用"
32. **付费墙/Cloudflare 文献全文获取阶梯（Crossref → Jina → Semantic Scholar → Wayback Machine）**：OECD 报告等被 Cloudflare 挡的公开文献，按序尝试：①`api.crossref.org/works?query.title=...` 拿 DOI/出版日期（至少能写引用）；②`r.jina.ai/<url>`（Jina Reader）读被 Cloudflare 保护的 HTML 页面（免费、无需 key，能拿到摘要/关键信息）；③`api.semanticscholar.org/graph/v1/paper/DOI:...?fields=openAccessPdf` 确认开放获取并拿到 PDF 直链；④直链仍 403 时用 Wayback Machine：`archive.org/wayback/available?url=<pdf直链>` 拿最近快照，或 `web.archive.org/cdx/search/cdx?url=<前缀>*&output=json` 列全部存档，再下载 `https://web.archive.org/web/<timestamp>if_/<pdf直链>`（`if_` 返回原始文件）。本会话用此阶梯拿到 OECD《Towards a common reporting framework for AI incidents》全文 PDF（2.5MB/27 页），使 crosswalk 从"框架级、投稿前需核对"升级为**逐字段实证**（29 criteria/8 维度/7 mandatory，Annex B Table B.1），并归档全文到 `08_evidence/` 作为证据源
33. **删除的内容要留"废弃类比登记册"**：把被删的 G²/Noether/守恒律/时间膨胀等登记为 abandoned-analogies register（为何删、用什么替代、禁止回潮），便于答审稿人版本差异问题，防止未来版本把旧概念当新想法重新引入
34. **学术三线表（booktabs）是用户默认表格偏好**：投稿文档所有表格必须是三线表（顶线 1.75pt + 表头下线 0.75pt + 底线 1.75pt，无竖线、无内横线）。docx 用 python-docx 操作 XML：tblBorders 设 top/bottom=single sz=14、left/right/insideH/insideV=nil，再给表头行每个单元格 tcBorders bottom=single sz=6；注意先移除 tblPr 里旧 tblBorders 与 tblStyle（Table Grid 样式会强制网格线）。PDF（pandoc/xelatex）加 `-V booktabs=true` 即三线表。验证：LibreOffice headless `soffice --headless --convert-to pdf` 渲染 docx + pymupdf 截图 + vision 确认只有三条横线；注意 soffice 输出到 Windows Temp 而非 MSYS /tmp。md 源文件保持标准 Markdown 表格（GFM 语法必须有竖线），三线表只保证在 docx/PDF 交付格式；xlsx 数据表不做三线。可复用脚本 `scripts/docx_three_line_tables.py`
35. **Cell Press/Patterns 投稿特有格式 + OSF/Zenodo 预注册边界**：Cell Press 要求 Resource availability 三段式（Lead contact 全名邮箱 / Materials availability 无新材料也写 "This study did not generate new unique reagents." / Data and code availability 引用 FAIR 仓库如 OSF/Zenodo），以及 "Declaration of generative AI and AI-assisted technologies in the writing process" 标准语句（放 Declaration of interests 之后，格式见 references/cell-press-patterns-submission.md）。OSF/Zenodo 预注册：**账号创建与公开提交必须用户本人**（邮箱验证+人机验证+学术承诺，AI 不能代），但 agent 全包其余：预注册文档（标题/摘要/材料清单/试点 estimands/信度协议/停止规则）、上传材料包 zip、中文逐步指南；用户注册后 agent 回填链接到 Readiness Checklist / Data and code availability / README。注意回顾性审计不能预注册，预注册的是未来试点的方法承诺
36. **hash manifest 自引用陷阱**：生成文件清单时若把 manifest 文件本身列入清单再写入，自身 hash 必变 → 永远 1 条不一致。生成/验证循环里必须排除 manifest 文件本身（`if fn == 'hash_manifest_v23.jsonl': continue`），并排除 __pycache__/大文件（>50MB）
37. **NHANES 跨周期队列列名/格式不一致**：P 系列（2017-2020）与 L 系列（2021-2023）虽是同一调查体系，协变量列名和格式可能不同——本会话 P 系列无 gender_cat/DM 列（gender 是数值型、需手动 factor）、无 TyG 列（需从 FBG×TG 重算且对数底要统一），L 系列则已有。跨周期合并分析前必须：①打印两队列 names() 对比 ②缺失列手动补（gender_cat=factor(ifelse(gender==1,...)) 等）③TyG/TyG-WHtR/TyG-BMI 派生指标统一公式重算 ④weight 列名不同（WTSAFPRP vs WTSAF2YR）映射到统一列。不做这步必然报 \"找不到对象'gender_cat'\" 或分析样本静默变小
38. **增量价值（ΔAUC）比较的配对检验**：base 模型 vs base+指标 的 AUC 比较必须用同一样本上的 roc.test(method=\"delong\")（配对），报告 ΔAUC + P 值；把 BMI/WHtR/TyG/GLM7 的 ΔAUC 放同一张对比图（AUC 误差棒 + ΔAUC 标注）。诚实叙事：GLM7 ΔAUC 小于 BMI 时结论写\"增量有限、主要信息来自年龄和肥胖组分\"——这是审稿人点赞的定位
39. **跨周期权重缺失要如实报告**：P 系列全队列 weight 缺失可高达 67%（仅空腹亚组有 WTSAFPRP），GLM7 缺失 71%——筛选流程图的每步人数和缺失比例都要写进方法/结果，审稿人（ChatGPT 点名）要求"每一步排除人数、纳入与排除者比较、各变量缺失比例、完整病例偏倚讨论"
40. **复合指数"去年龄敏感性"是必做分析**：指数含 age 组分时（GLM7 内含 age×BMI），审稿人必问"关联是否纯粹由年龄组分驱动"。敏感性：全调整模型去掉 age 协变量重跑——OR 保持则证明非纯年龄驱动（本会话 GLM7 去年龄后两周期 OR 均 1.85，比含年龄的 1.73 略高，成为关键证据）；同时 M3b 过度调整（base 模型 + BMI + waist）后 OR→null（1.226/0.819 不显著）正是"肥胖组分解释大部分关联"的核心诚实发现，写进结果和讨论，不是缺陷而是定位
41. **重定位后单指标 ROC 移补充材料**：论文定位转为关联/增量价值检验后，单指标 ROC（GLM7 vs TyG）不再是主图（主图让位给增量价值 AUC 对比图），移到 Figure S1（双周期并排 + DeLong P 标注）；只报告 AUC 不足以证明临床预测效用，保留预测模型表述须 TRIPOD+AI
42. **Supplementary Materials.docx 生成模式**：python-docx 生成（Table S1-S3 三线表 + Figure S1 嵌入 + Appendix 可复现性声明/R 代码变量映射表声明），数值必须来自重算 rds 而非论文正文复制；生成后主文稿补 "Supplementary Tables S1–S3" 引用——注意 python-docx 匹配替换串时用正文实际措辞（含复数 "Tables S1–S3" 而非 "Table S1"），且替换文本跨 run 时整段重建首个 run
43. **docx 终检：正文必须有 Figure 引用 + 图题 legends，且内容可能藏在 doc.tables 里**：BMC/Elsevier 投稿硬性要求——①正文每张图都要被引用（`re.findall(r'Figure\s*(\d+)', full)` 应覆盖 1..N），②References 前必须有完整 Figure legends（每图一句加粗标题 + 说明）。本会话 v7 论文标题页声明 "Figures: 5" 但正文 Figure 引用和 legends 全空（0 处）——这是最容易漏的投稿阻断项。修复：正文锚点句补 "(Figure N)"（按 Results 叙述顺序：流程图→森林图→四分位→增量 AUC→RCS），References 前逆序 addprevious 插入 legends 段（加粗标题 + 10pt 正文）。另：**Title page 的 Manuscript statistics（字数/表/图/文献计数）和 STROBE checklist 内容都在 doc.tables 里**，只扫 doc.paragraphs 会误报 "Word count MISSING / STROBE 空"——核查脚本必须同时遍历 doc.tables（含单元格文本）再下结论
44. **终检脚本的"检查命中"要覆盖表格+图注**：判定"某元素是否存在"（如 Keywords、Competing interests、Table S1 引用）时，把段落文本 + 所有表格单元格文本拼成一个 full 字符串再搜；只看段落会把表格内容误报为缺失（本会话 Title page 统计表、STROBE 33×4 清单都被段落扫描误判 MISSING，实际完全正常）

### 组学 Atlas 稿件专项（跨队列公共组学 v08→v09 实例：GPT6 第一性原理评审 → 先 rerun 后改文）
对\"N 队列×M 模块\"公共组学图谱稿，GPT6 型评审（会自己推导\"什么分析不可能证明什么\"）最常命中的是**统计实现级**问题，命中必先回到代码重跑、数字定稿后再改正文——本会话实测重跑后核心数字全变（组成稳健 19→6、meta 显著 73→31 / 4→11）：
1. **组成校正必须用联合模型，不能\"先对成分残差化再检验\"**：`模块 ~ 疾病 + 成分(epi/fib/end/imm) [+ patient]`（配对保留患者因子），逐队列逐模块给效应 d_adj=β/σ_resid、SE、p；残差化两步法会高估\"校正后仍稳健\"状态数（xCell 残差 19 vs 联合模型 6，重叠仅 5）。不要拿 xCell 富集分数当\"细胞比例\"；EPIC-xCell 一致性差（上皮 ρ=0.09）时如实写\"工具间低一致\"而非\"验证\"。
2. **Meta 效应量必须先统一尺度再谈 DL/REML/HK**：配对 d_z（差/SD差）与未配对 Hedges' g 不同尺度，混池是审稿人必抓点。换算 g_eq = d_z·√(2(1−r))，r 用配对模块分数实证相关（样本太少再回退 0.5 并做 r=0.3/0.7 敏感性）；配对方差 V=2(1−r)/np+g²/(2(np−2))。区分\"方差估计器（DL/REML）\"与\"推断调整（Hartung-Knapp t、k−1 df）\"，别概括成\"DL 不保守 REML 保守\"。注意：统一尺度后部分配对队列实证 r 极高 → CI 极窄，需敏感性复核。
3. **外部队列先做身份/样本数审计再解释**：GEO 阵列数 ≠ 原论文样本数 ≠ 可分析数（GSE39582：585 阵列、579 带 OS、573 可分析/190 事件——原论文\"566 原发+19 癌旁\"不是矛盾，需逐层排除计数、重复患者、癌旁是否混入、事件定义）；每个外部阳性补年龄/分期校正与 95%CI，外部阴性给 CI 区分\"方向一致但宽/减弱/反向\"。
4. **\"逐级筛选\"叙述要有证据矩阵支撑**：写一张每行一个状态的矩阵（原始效应｜逐队列｜统一尺度 pooled±CI｜联合校正后｜单细胞支持｜外部预后），集合无交集时明确说\"不同层回答不同问题\"，不要渲染成\"同时通过所有严格层\"的漏斗（正文\"55→19→sc→预后\"式叙述在审稿人按名单核对后必被拆穿）。可结合 GPT6 建议把预后降为独立延伸层、DepMap/CPTAC/药物移补充材料。
5. **用户要求\"写未使用 AI\"等与事实相反的声明时拒绝并给合规替代**：AI 实质参与了分析脚本与文本时，先明确无法代写虚假声明，给出标准/最小披露措辞；用户知情后仍决定省略披露的，删除声明并保留内部提示（投稿系统往往单列 AI 问答），不写正面谎言。Zenodo DOI 在全部数据公共时不是义务，可删除并改\"随稿发布 GitHub\"。
6. **联合模型/任何含 factor(group) 的 lm() 先做符号校验（v9 实测最大隐性 bug）**：R 的 lm/coxph 把 factor 参照系默认为**字母序第一个水平**——`group` 取值为 Case/Control 时参照是 \"Case\"，抓到的系数是 `groupControl` = Control−Case，**方向与常识相反**。症状：证据矩阵里 raw median SMD 为正（CRC WNT +2.59）而 joint d_adj 为负（−2.47），或反之——凡\"联合/校正后效应与原始方向大面积相反\"先怀疑符号约定而非生物学。修法：`dat$group <- factor(group, levels=c(\"Control\",\"Case\"))` 让系数名=groupCase（Case−Control），或统一取 −coef。**纪律：每建一版\"raw vs 校正\"对比矩阵，先断言校正效应符号与 raw 主流方向同侧（至少对 head 状态抽验），再做 robust 计数/写正文**——符号 bug 会静默污染全部\"校正后稳健集合\"的方向叙述。
7. **整稿 md 的\"批量 replace 升级\"必须带命中/漏报报告 + 二次修补脚本 + 区块级重写兜底**：一次 30+ 条 old→new 的 python 替换，因锚串大小写（句子中段\"Standardized\"实为\"standardized\"）、换行假设（md 长段落单行 vs 以为有 \n）、Unicode 转义（× vs \\u00d7）等必然漏 3-8 条。模式：①每个替换打印 `ok/miss: 锚前 70 字符` ②miss 清单单独二次脚本（用大小写不敏感/去换行后的变体、或正则切片在定位点重建整句）③跑完后 grep 旧口径短语清单（\"19 remained\"、\"carried entirely\"、\"Methods 2.10)\" 等）确认零残留 ④摘要改写优先\"索引切片整段替换\"（`s[:i]+new+s[j:]`），不要逐句 replace——批量插入会使词数膨胀（本会话 250→318），切片替换后立即数词回校到期刊限长。
8. **rerun 数字必须落到\"证据矩阵 CSV\"再进正文，图/表/摘要数字从矩阵派生**：联合模型稳健 6、统一 meta REML/HK 11 这类新数字先在矩阵（raw/逐队列/unified meta±CI/joint d_adj/sc 命中/外部预后分格）里定稿，正文替换与 Table 1（per-context 行：robust/REML-HK/joint/xCell-residual/external）只引用矩阵汇总；符号修完重跑矩阵确认 tier 不变再改文——\"先出可核验新数字、后写文字\"的顺序（用户已确认）能避免改两遍。

9. **引文审计/重排解析器必须展开区间 token（v9 实测：30 条\"孤儿\"是解析器没识别 `[21-50]` 连字符区间）**：Methods 2.1 用 `Supplementary Table S1 [21-50]` 引用 30 条队列出处文献时，只支持逗号列表 `[9,10]` 的扫描器会把 21-50 全报成 uncited（孤儿 30 条假警报），而真实问题是首次出现顺序违规（如 9,10 出现在 4-8 前、方法区 20→19→16→15→14 倒序）。正确实现：token 展开须同时处理逗号与**连字符/en-dash 区间**（`9,10` 与 `21-50`/`21–50`），先审计（悬空/孤儿/**首现顺序违规**）再决定是否重排。重排 = 按首现顺序建 old→new 映射 → 全部 token 重写 → References 表按新号重排 → 断言违规 0 + 列表 1..N 连续 + 摘要无引用；**md 重排后必须重建 docx/pdf**（引用号变化不重建 = 交付物与源不一致）。副作用要主动告知用户：严格首现规则会把区间引用的方法/出处文献群（如队列出处 14-43）排在方法引用（GSVA 44 等）之前，若用户偏好主题分组编号需先问再切。可复用工具：`scripts/citation_audit_renumber.py`（审计 + `-r` 重排）。
