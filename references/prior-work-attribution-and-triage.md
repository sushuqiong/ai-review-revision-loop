# 对他人工作的归属核原文 + 收敛轮三分类取舍

来源：课题2 GLM7×胆石症 **v17→v18 轮**。两件事都是这轮才浮出来的：
一件是**把他人的工作写成做了它没做的事**（可被判不实）；一件是**该停手时不停手**。

---

## 一、归属声明必须逐行核原文（不可凭印象填写）

### 1.1 触发场景

写这类论文时几乎必然会做一张**对应表 / 贡献定位表**，三列通常是：

| 评论提出的问题 | 原作者回复**已完成**的内容 | 本研究新增 |
|---|---|---|

**第二列是最容易出错的一列**——因为它是关于**别人那篇文献到底写了什么**的断言，
而它比你自己的数据更容易被审稿人一键核对（审稿人手里就有那篇回复）。

### 1.2 本轮实测被抓出的四处不实（全部在第二列）

| 写法 | 原文实际是 | 性质 |
|---|---|---|
| 年龄组分贡献「讨论见 reply **section 5**」 | §5 讲的是 **p 值与置信区间的边际关系**；年龄在 **§2.1 与 §3** | 章节号错位 |
| 判别力问题「**已处理**（reply section 5）」 | 该回复**全文没有**任何相对组分的判别分析（无 AUC/ΔAUC）；只有 Fig 1A/1B/2 | **把他没做的事写成做了**（最严重） |
| 原文为「the original **single-source** report」 | 原文含 **NHANES 2013–2023 + CHARLS 2011–2020 两个来源** | 事实错误 |
| 回复「做了 missing values 的 MICE 敏感性」 | §4 明确限定为 **CHARLS 中胰岛素值的系统性缺失** | 表述过宽 |

⇒ 前三处都是**一句话就能被审稿人推翻**的；第四处属于"略微抬高"。**全部要改。**

### 1.3 做法（可脚本化）

1. **逐行核原文**：把参考文献 PDF 抽成文本（`pymupdf`），对每一行去 grep 关键词
   （组分数、AUC/discrimination、VIF、imputation、数据来源名），**定位到具体章节号与图表号**后才填。
2. **没做就写"Not reported"**，不要含糊、不要credit：
   > **Not reported**: the reply does not present a discrimination analysis (AUC or ΔAUC)
   > of the index relative to age or age plus BMI.
3. **表注写明填写约定**（这一句能一次性关掉整类追问）：
   > The second column records only what the reply reports; where the reply did not address
   > an item, that is stated explicitly rather than counted as already addressed.
4. **收窄过宽表述**：把"missing values"这类泛称改为原文的实际范围。
5. **顺带做一次全文口径同步**：同一泛称若在摘要/引言/讨论多处出现，一起收窄
   （本轮实测 4 处），否则首尾不一致。

### 1.4 与之配套的检索义务

填第二列之前，**必须先确认自己找全了"前人已做"**——检索义务见
`manuscript-consistency-and-scale-checks.md` 的 **§F**（评论信/correspondence）与
**§F2**（同结局 × 同指标的已发表实证比较）。**没检索就填表 = 一定会有行填错。**

## 二、收敛轮三分类取舍 + 该停手的信号

### 2.1 用户明确确认的取舍规则

到后期收敛轮，审查意见会从"实质错误"变成"形式要求"。**收到意见先分三类，再决定做哪些**：

| 类 | 判据 | 处置 |
|---|---|---|
| **(a) 必须修** | ① **数字自相矛盾**：同一量在同一稿或同一份补充材料里出现两个值，或两处表格直接打架；② **可被判不实的 claim**：对他人工作的归属、"已完成"的描述（见第一节）；③ **会被直接质问的核心参数解释缺失**：例如同一参数在两表里方向相反（0.826 vs 1.014）却全文无说明 | 立即修，且**留一条可复算的溯源记录** |
| **(b) 接受并如实披露** | 措辞、元数据口径、格式、篇幅、**期刊相关设置** | 不改；写进"已接受未修"清单 |
| **(c) 不要做** | 新增分析种类、把已下沉到补充材料的数字再搬回正文 | 拒绝 |

**为什么 (b) 类不必强修**：这类项**本身就取决于目标期刊**，只有真实投稿流程才能收敛。
（本轮实例：Cover letter 未写期刊名、摘要 342/348 词是否超限 —— 不知道投哪本刊就无法定。
这恰恰说明：**这一层必须交给真实投稿，而不是继续自审。**）

### 2.2 该停手的信号（本项目最有价值的一条）

**当"我必须修的"清单清空、剩下的全是 (b) 类时，继续批量编辑是净负收益。**

实测证据（同一课题、连续两轮）：

| 轮次 | 修掉的问题性质 | 该轮批量编辑**新引入**的缺陷 |
|---|---|---|
| v12→v14 | **实质**（年龄分支丢 2,710 人、bootstrap SE 低估 ~30%、尺度假象） | 少量 |
| v15→v16 | 口径与表述（腰围口径、IPW 分母、自由度措辞） | 中等 |
| **v17→v18** | **形式与定位**（样条术语、AUC 表述、代数压缩） | **2 高 + 8 中** |

⇒ **修掉的越来越轻，引入的越来越重。** v18 那 8 个中危里有 6 个是当轮自己改出来的。

**所以此时应当主动做的事**（而不是继续打磨）：
1. **主动向用户提出三分类**，说明哪些必修、哪些建议接受、哪些不做；
2. **明确给出"建议投出去"的判断**及理由（已知错误已清零；剩余项依赖期刊）；
3. 用户会选"折中"，并**要求如实列出"已接受未修"清单**。

### 2.3 采纳取舍后必须交付的东西

- **"已接受未修"清单写进 README 与交付说明**，逐条给：项目 | 现状 | 为何接受 | 何时会需要处理
  （典型：目标期刊定了之后）。**不要藏、不要含糊成"其余为小问题"。**
- 交付说明里同时给出**终验结果**（未通过项数、每项判为"文档真错"还是"检查口径错"）。
- 记录**(a) 类的每一项**修了什么、依据哪个输出文件 —— 这部分是将来应对审稿人的弹药。

### 2.4 一句话判据

> **"我这轮要修的东西，还能改变读者对结论的理解吗？"**
> 不能 → 它在 (b) 类 → 不要为它再动一次全局编辑；
> 能 → 它在 (a) 类 → 修，并留下溯源。
