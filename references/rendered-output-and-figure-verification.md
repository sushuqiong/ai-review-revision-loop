# Rendered-output & figure verification (docx→PDF→text order; figure OCR)

Companion to this skill's submission-readiness checklist. Everything here is machine-checkable
and needs **no vision model**. Use it before claiming a version is finished, and specifically
whenever the user says "格式有问题", "图表不符合学术风格", or "你不是可以调用OCR吗".

## 1. Verify the RENDERED document, not just the markdown/docx source

Splice-editing a long markdown manuscript repeatedly pushed a section heading to the END of the
file, interleaved supplementary tables with figures, and duplicated tables — paragraph-level
checks missed it until the user opened the file. Always render first:

```bash
# LibreOffice headless (Windows path; soffice must NOT be running interactively)
soffice --headless --convert-to pdf --outdir <tmp> Manuscript.docx
```

```python
import fitz, re
d = fitz.open(pdf); full = re.sub(r"\s+", " ", "\n".join(p.get_text() for p in d))
# structural assertions (normalise whitespace FIRST: PDF line-wraps headings)
assert full.find("Supplementary material") < full.find("Supplementary Table S1.")
assert full.find("Figure legends")        < full.find("Figure 1.")
assert full.find("Tables")                < full.find("Table 1.")
pos = [full.find(f"Supplementary Table S{n}.") for n in range(1, 18)]
assert all(p >= 0 for p in pos) and all(pos[i] < pos[i+1] for i in range(len(pos)-1))
print("last content:", full[-80:])   # must be the LAST supplement's text, not a heading
```

Canonical order the user expects: body → Declarations → References → **Tables → Figure legends
(figure + caption) → Supplementary material (S1…Sn ascending)**.

## 2. Figure QA by OCR (catches garbage figures text-only review cannot)

Call the **Tesseract CLI directly**. `import pytesseract` can fail with
`ValueError: numpy.dtype size changed … Expected 96 … got 88` when the venv's pandas was built
against a different numpy — the CLI has no such dependency:

```bash
tesseract fig.png stdout --psm 6      # or --psm 11 for sparse/plot text
```

Checks that paid off:
- **Assert expected values are present** (per-figure list of HRs/CIs/counts): a missing number
  means clipping or a broken label column.
- **Assert `"NA ("` count == 0.** A subgroup figure generated by *parsing a markdown table* came
  out as `NA (0.926-NA)` on every row while looking plausible at thumbnail size.
- **Edge-touching text = clipping**: run `--tsv`, take each text box, flag any whose `left<=3`,
  `top<=3` or right/bottom within 3 px of the canvas. Zero such boxes is the pass condition.

Hard rule learned: **never build a figure by parsing a markdown table.** Transcribe/derive the
values in the plot script, `stopifnot(!any(is.na(rbind(hr, lo, hi))))` before `ggsave`, then
OCR-verify. This is the single highest-yield figure check for this project.

## 3. Splice-safe markdown maintenance

- **Never** `re.sub(r"\s+", " ", s)` on a whole markdown file — it destroyed every newline once
  and flattened the manuscript into one paragraph. Collapse whitespace **within lines only**.
- After any block insert/move, validate: count `^## Table \d+\.`, `^\*\*Supplementary Table
  S\d+\.`, `^!\[Figure \d\]` markers (no duplicates), assert supplement numbers ascend, and
  compare total word count against a backup (`cp` before editing) — a jump signals duplication.
- Ordering repairs are safest as a **line-based rebuild**: walk lines, classify
  table/figure/supplement blocks, drop old section headings, then reassemble in canonical order.
  String `.replace()`-based removal silently misses when the captured block includes different
  whitespace, producing duplicates downstream.
- Rebuild the .docx from markdown with pandoc, then apply three-line table borders in python-docx
  (top/bottom 1.5 pt = `w:sz 12`, header rule 0.75 pt = `w:sz 6`, `insideV/insideH = none`).
  Use the same interpreter that has python-docx installed (here `D:\ProgramData\python.exe`).
- A reference-renumbering script silently pointed at the **previous version's .md** for many
  rounds (symptom: "total refs" stuck at the same constant no matter what was edited). Check the
  script's target path whenever a count looks frozen.
- Funding/grant numbers in brackets (`[2023]1`) are parsed as citations by citation scanners —
  write them without brackets (`2023-1`).

## 4. Tooling / config notes (fix, don't avoid)

- Vision tool returning `404 … model … or Permission denied` means `auxiliary.vision.model` in
  `config.yaml` names a retired model. Repair with the CLI (direct file edits are refused by the
  config guard) and tell the user a **session restart** is needed because config is read at start:
  `hermes config set auxiliary.vision.model kimi-k3-code`  (provider must declare `supports_vision`)
- Until vision is live, OCR + PDF-order assertions cover legibility/clipping/structure; say so
  explicitly instead of claiming "I cannot see the figures".

## 6. R/analysis pitfalls that recurred (keep scripts runnable)

- `%<>%` requires `library(magrittr)` — use plain `d <- d %>% mutate(...)`.
- `ns()` requires `library(splines)` inside every script that splines.
- `coxph()` called inside a helper function can fail with "object 'x' not found" — fit at top
  level (this skill's main reference documents the same trap).
- `concordance(fit, newdata=, weights=)` is invalid (weights are not accepted there).
- Long `Rscript -e '…'` command lines segfaulted on this box; write a `.R` file and run it.
- Bootstrap resampling that refits weighted Cox models hundreds of times can segfault at n≈21k —
  cap B (100–200) and/or evaluate on a fixed subsample, and report the design.
- `summary(survfit(...), times=<vector>)` errors when `extend` is length>1 — use
  `approx(km$time, km$surv, xout=...)` for censoring weights (also lets you truncate them).
- Graf/IPCW Brier with heavy administrative censoring is unstable (values jumped 0.05→0.60 with
  naive truncation): prefer the **administratively complete window** (cycles that can all reach
  the horizon) as the primary evaluation and report IPCW only as sensitivity, with the
  truncation level and its assumption stated.
