# 渲染级版式质检与"修一个坑冒另一个坑"的回归陷阱

来源：一次 16 轮的数据资源稿构建（26 队列 / 10 情境 / 4 图 / Table 1 + S1–S30）。本文件补两件事：
**在没有视觉模型的情况下如何证明"图表没问题"**，以及**修复轮里反复出现的自伤型回归**。

## 1 · 为什么不能只做字符级检查

字符数统计既会假报警（把 "not testable" 当成图例里的 "table"），又会漏掉真问题（列宽不够导致文本越出页面）。
本用户对图表的容忍度极低，且会明确质问"图表也是学术风格、没有你经常犯的错误吗"——所以要用**渲染产物**
上的像素与词框证据回答，而不是"我检查过了"。

## 2 · 三类可程序化的检查（按证据强度排序）

### (a) 渲染页词框级（最强，替代"看图"）
用 PyMuPDF 取每一页的 word bbox，判两件事：

```python
import fitz
doc=fitz.open(pdf)
for page in doc:
    W,H=page.rect.width,page.rect.height
    ws=page.get_text("words")                      # (x0,y0,x1,y1,text,...)
    overflow=[w for w in ws if w[2]>W-1 or w[3]>H-1 or w[0]<1 or w[1]<1]
    # 重叠：仅比较相邻窗口内的词，交叠面积 / 较小词面积 > 0.45 记为碰撞
```

判决标准：**overflow=0 且 overlap=0**。实测：39 页补充材料 PDF（8,623 词）与 6,300 词正稿均 0/0。
覆盖了表格单元格越界、图注压字、页边裁切三类问题。

### (b) 图像像素级（图件专用）
* 外圈 2 px 墨迹 = 0（否则是裁切/出血）；
* 打印尺寸：宽 ≤6.7 in、高 ≤23–24 cm @ 目标宽；PNG ≥300 dpi；
* 缩小 50% 后 OCR 词数 / 原尺寸词数 ≥0.75（可读性）。实测由 0.60 提升到 0.83 后达标；
* 图内不得出现图例/总标题：用**词边界**匹配 legend/figure/table，否则 "not testable" 会假报警。

### (c) 文档级一致性
* md 改了必须立刻重建 docx/pdf，并断言"每个段落都能在 docx 里找到"；
* 内嵌图与磁盘图逐字节比对（SHA-256），要求 N/N 一致；
* "Figure captions" 只允许出现一次（图注文件与构建器各加一个标题是常见重复源）；
* 上标引用计数、脚注/单位上标（`^1`）必须渲染为真上标。

## 3 · 回归陷阱清单（每一处都在本会话真实发生）

| 改动 | 造成的回归 | 防护 |
|---|---|---|
| 把主表重新内嵌进 docx | 表从正文消失（`len(doc.tables)==0`） | 每次重建后断言表数量 |
| 全局把连字符换成 en dash | **DOI/UUID/版本号内部被改坏**（`10.1186/s13059-021-02533–6`） | 转换前先保护标识符：DOI/UUID/URL/accession/版本串；页码与数值区间才换 |
| 新增一个 QC 文件 | 该文件未进清单 → `sha256sum -c` FAILED | 清单最后重建，然后立刻 `--check` |
| 重命名表文件 | 补充材料编号漂移（S1–S17 与 S18/S19 混用） | 单一"补充材料清单表" + 引用存在性校验 |
| 用 `re.sub(r"⟪([A-Za-z_0-9]+)⟫", ...)` 给占位符编号 | 队列文献块的占位符被整体清空 → 参考文献少 27 条、编号断裂 | 占位符编号时对"块占位符"单独分支，并断言 `cited == 1..N` |
| 反向引用写成 `\17` | 被解析为第 17 组 → 静默错文 | 用 `\g<1>7` |
| 前一次把整行折成一行（`re.sub(r"\s*\n\s*"," ",md)`） | 参考文献块被压成一行、正则再也匹配不到 | 只对目标块做折叠；改动前先备份/从 git 取回 |

## 4 · 每次修复轮之后必须重跑（顺序固定）

```
1. 重建 md → docx → pdf → 补充材料 pdf
2. 图件像素级质检（crop/legibility/图内无图例）
3. 渲染页词框质检（overflow/overlap）
4. 清单重建 + sha256sum -c
5. 数字一致性（正文每个头条数字 vs 随包 CSV）
6. 占位符扫描（to be inserted / TBD / XXX）
```

**教训**：修复引入的缺陷比原始缺陷更难发现，因为它们发生在"已经检查过"的文件上。审计放在修复之后、
以"修复后产物"为对象，而不是以"我以为改好的源文件"为对象。

## 5 · 与用户沟通时的表达方式

* 给数字，不给形容词：`overflow 0 / overlap 0 / 129-129 verified / legibility 0.94–0.99`；
* 报告时必须区分 **FAIL / WARN / 假阳性**，并说明假阳性为什么是假阳性（如"对比度 1.4"其实是 OCR 单字符碎片）；
* 明确写出机器证不了的部分（审美、配色），并请用户目检具体文件路径——不要用"应该没问题"糊过去。
