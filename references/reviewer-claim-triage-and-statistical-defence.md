# 审稿意见的事实核对（triage）与统计质疑的正面防守

适用：外部 AI（GPT6 / 腾讯 Hy4 / Claude）就同一稿件给出 numbered list 意见，需要判断"哪些真、哪些是误报"，
并在不改数据的前提下把可修项修到位、把不可修项如实披露。本文件是 `ai-review-revision-loop` 的支撑细则。

## 0. 铁律：先核对，再修，不盲从也不硬顶

对每一条意见做四步核对后才决定动作：**（a）读随包数据/脚本确认事实；（b）判断是"正文写错"还是"实现写错"；
（c）能修就修并留证据；（d）确认意见本身是误报时，在响应表里写明依据。**

实战例（v15→v16 的 LOG2 转换规则意见）：
- 审稿人："integer fraction >0.90 且 max>50 视为已 log，否则 log2 — 这个规则写反了。"
- 核对结果：**正文句子确实写反了；代码与数据是对的**——读 `transformation_summary_per_cohort.csv` 得
  27 个队列 integer_fraction ≤0.033、input_max ≤17.9，全部走"已对数化、不转换"分支。
- 正确处置：改写正文为代码的真实方向（"仅当像原始强度/count 时才 log2(x+1)"），并补一句"若像 counts
  须先做文库归一化，管线只标记不静默转换"；**不要**去重跑整条管线。
- 教训：审稿人指出"算法可能写反"时，**文本 / 代码 / 数据三者要分别验证**，结论常常是"文档错、实现对"。

## 1. 统计质疑的正面防守配方（四件套）

被质疑"效应量定义/合并方式"时，仅解释不够，要出**可复算证据**：

1. **写出公式**（分母是什么、修正项是什么，明确命名，例如 SMDH = J·(m_case−m_control)/√((s²_case+s²_control)/2)），
   并声明它不是经典 Hedges g 的样本量加权合并 SD。
2. **蒙特卡洛验证方差公式**：对一组 (n1,n2,效应量) 网格各模拟数千次，比较"解析方差 vs 经验方差"的比值与
   名义 95% 区间的实际覆盖率。本项目结果：比值 0.92–1.03（中位 0.97）、覆盖 0.94–0.95 → 方差可用。
3. **用常规约定重算整层做敏感性**：如非配对改用样本量加权合并 SD 的 Hedges g、配对改用 d_z·√(2(1−r))，
   然后报告**同号比例 / 中位绝对差 / 最大差**。本项目 163/165 同号（99%）、中位 0.014 → 结论不依赖分母约定。
4. **按设计分层报告**：把"配对(SMCRPH)与非配对(SMDH)混在一个合并估计"改为**分层并列**（联合 / 仅配对 /
   仅非配对），逐状态标注每个队列贡献的度量。同时报 unpaired-only 敏感性。

补充：**有影响力的低 n 队列要做排除敏感性**而不是写备注。本项目 GSE62232（仅 5 个对照）——HCC 全部 17 个
状态仅由 2 个队列支撑，去掉它后全部降为单队列 → 一律标 not estimable，并在表中把该层标为最不稳健部分。
这类"一去就塌"的结论本身就是可发表的诚实信息。

## 2. 数字对账：审稿人最爱抓"每段都合理但合不起来"

- 建**唯一清单表**（本项目的 `input_dataset_status.csv` + `curation_flow_reconciled.csv`）：每个输入一行，
  列＝来源/层/是否入估计/是否有可检验比较/原因；流程表要能**相加闭环**（本项目 31 = 26 病例-对照 + 1 应答 +
  1 外部验证 + 3 下载未采纳）。
- 补充材料编号凡是出现多套（S1–S17 / S18 / S20）就必被追问：建**唯一清单表**逐项标注"随主稿提交 / 仅仓库提供 / 内容"，
  全文统一为一个连续区间（本项目 S1–S30），并加程序化校验"正文引用的每个表都必须存在"。

## 3. 引用与编号的隐蔽坑

- **accession 与上标粘连**：`GSE13911` 后紧跟角标 3，抽取文本变成 `GSE139113`，审稿人会当成编号抄错。
  处置：accession **平铺列出**，队列文献统一用**区块引用**（"(references 8–34)"）+ 清单表映射。
- **区块引用的编号实现**：占位符必须在**同一次替换**中展开为 `N–M`；若先按 key→number 映射、占位符不在映射里
  就被替换成空串，编号会断裂（队列文献被吞、连续性校验失败）。做法：`re.sub` 的 lambda 里显式处理 block 键，
  并让连续性校验支持"范围引用"（解析 `⟦a–b⟧` 后展开）。
- 元数据源（Crossref）会返回**更正通告（Correction）**、含 HTML 标签的题名、缺作者记录：引用必须做
  "排除 Correction / 清洗 `<i>` `<b>` / 集体作者兜底（如 The Cancer Genome Atlas Research Network）"。

## 4. 质检器本身会骗你：先排除假阳性，再动稿件

本项目多个"问题"其实是检测器缺陷，务必先判性质：
- **子串误判**："not testable" 含 "table" → 图内图例检测必须**整词匹配**（`\btable\b`）。
- **标识符误判**：DOI/UUID/版本串里的连字符被当成数字区间（`2026-09` → "6-0"）。检测前先剥离
  `10.\d{4,9}/...`、UUID、`https?://...`、`v\d+\.\d+-[a-z]+-\d{4}-\d{2}`。
- **重叠正则重复计数**：`https://doi.org/[DOI …]` 同时被两条正则命中 → 占位符计数虚高。用**一条合并正则**报数。
- **字符数猜测不可靠**：判断"单元格是否溢出"别用字符数阈值；改用**渲染级检测**（见 §5）。

## 5. 渲染级验证（比任何启发式都强）

用 PyMuPDF 直接查**已渲染 PDF**的词框：
- 越界/裁切：任一词 `x1 > page.width-1` 或 `y1 > page.height-1`（或 x0/y0 < 1）。
- 文字重叠：取相邻词对，交叠面积 / 较小词面积 > 0.45 记为碰撞。
本项目正文 PDF（6,346 词）与补充材料 PDF（8,623 词）均 **0 越界 / 0 重叠** —— 这才是可以写进回复的结论。
图件侧另做：**边带墨迹**（最外 2 px 是否有墨 → 裁切/出血）、**缩 50% 后 OCR 词数比**（可读性）、墨迹密度。
可直接调用 `scripts/pdf_docx_figure_qa.py`（本技能自带）。

## 6. 构建产物同步与结构自检

- 顺序固定：`md → docx → pdf → 表格 docx → SI pdf → inventory/checksums → zip → push`，**一次脚本内完成**。
- 每次都要跑**结构自检**，因为"重写构建器"会静默丢东西：本项目 v16 重写 docx 构建器时 **Table 1 掉了**，
  审计项 `tables embedded >= 1` 才抓回来；另有 `'Figure captions' 出现次数 == 1`（图注文件自带标题会重复）、
  `md 每段必须出现在 docx`、`内嵌图 sha256 与磁盘一致`、`上标 run 数 > 0`。
- 清单设计：`checksums_sha256.txt` **只覆盖数据文件、不含自身**，清单文件自身的摘要另写
  `manifest_checksum.txt`。正文里不要再写"因为两个文件自引用所以少两条"。

## 7. 数据资源稿的其它必备动作

- **干净目录复现测试**：把 deposit 复制到临时目录，跑随包示例脚本，比对声明值（本项目三例 exit 0，
  且 0.818 中位比、9/17 方向一致均复现）。脚本改为**从自身位置向上找 `00_VERSION.txt` 推根目录**，实现零硬编码。
- **版本统一**：稿件版本号 / 仓库 tag / README / manifest 必须一致；若模块定义自 v12 冻结而与发布号不同，
  **显式加版本说明**而不是让它裸奔（"module_version = v12.0-frozen；自 release 12 冻结、本版未改动"）。
- **源数据可追溯**：为每个 accession 记录检索日期 + 本地重建输入 sha256 + 提供方 URL（`source_download_manifest.csv`）。

## 8. 隐私与可获取性的平衡（本用户硬要求）

- **仓库默认私有，绝不自作主张公开**；审稿期可写明"repository is private during review, editors and reviewers are
  granted access on request"，同时**把代码随数据包公开发布**（deposit 内有 `11_code/`），这样既保隐私又满足
  数据期刊的代码可获取要求。
- 交付位置：**Zenodo 包放在项目目录内**（如 `…\EGFR\★Zenodo上传-就选这个_vN.zip`），不要堆在桌面；
  **用户没点名就不要生成"投稿上传"包**（一次点名后即成为默认：只给 Zenodo 包）。
- 交付夹不留冗余变体：旧版本稿子移入 `_archive_previous_versions/`，根目录只留当前版本。

## 9. 响应表（每轮必交）

对每条意见一行：`编号 | 意见 | 处置与证据（含新数值/新文件） | 位置`。末尾写"仍未闭环（需作者操作）"，
通常只剩 DOI 占位符与作者元数据。**处置栏必须含可核验的引用**（文件名/表号/数值），不要写"已修改"。
