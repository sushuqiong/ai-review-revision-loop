# 无视觉模型下的图件质检与"重叠/裁切"修复流程

> 来源：2026-09 EGFR v13→v14。用户反复强调"画图表总是有问题"，外部审稿人也点名"Fig1B/C 横轴不可读、Fig3A 标签堆叠、Fig3C 标题重叠"。
> 这台机器没有可用视觉模型 → 用 **OCR 文字层 + 像素判决** 代替人眼，可复现、可写进回复。
> 可直接运行的脚本：`scripts/figure_qa_pixel.py`。

## 0. 规格硬线
- 宽 **≤ 17.0 cm（6.7 in）@300 dpi**；单张图高 **≤ 24 cm**（超了会被判超单页图上限，Nature 系常用上限约 23–25 cm）。
- **图内不放总标题、不放上下图例**（用户硬性偏好）；图例单独成 Word 文件（`Figure_legends_*.docx`）。
- 表用三线表（booktabs：首行 top+bottom、末行 bottom、无竖线）且单独 Word 文件。

## 1. 三道机器检查
1. **几何**：`W/300*2.54` 得 cm，逐张核对宽高上限。
2. **裁切**：OCR 词框贴到画布边缘 **且**该边缘带（取最外 40 px）墨迹比例 >0.5% → 真裁切；只是框贴边、边缘全白 → 假阳性（本项目多次出现，务必做墨迹复核再下结论）。
3. **碰撞**：两词框垂直中心接近且水平区间相交 **且**交集矩形内墨迹占比 ≥2% → 候选碰撞。
   - **假阳性排除规则（关键）**：两框水平间隙 ≤3 px 且拼接文本为数字/小数点/正负号 → OCR 把 `0.94` 拆成 `0.9`+`4` 造成的自比自证；交集全白 → 也排除。
   - 实测：一份被审稿人判"严重重叠"的图，排除上述两类后 **0 真碰撞**；所以**先跑判决规则再改图，别急着大改**。

## 2. 让"重叠"根本不发生的版面规则（改图优先级从高到低）
1. **去掉整图总标题**（`patchwork::plot_annotation(title=...)`），标题过长会被画布右缘截断（曾残留一个孤立的 `r`，来自 "collinear**r**"）。
2. **面板标题自动折行 + 精简**：R 里用 `strwrap(x, width=38)` 包一层 `wrap_title()`；标题越短越安全（曾因 45 字符标题贴边被切掉 "ns"）。
3. **长标签移入轴名**：把柱旁的长文本（"tumour vs non-tumour|29 donors"）改成 y 轴的类别标签。
4. **分面换方向**：3 个分面横向并排会让 10 个类别挤在 1/3 宽度里 → 改 `facet_wrap(..., nrow=3)` 纵向堆叠，每面整幅宽。
5. **类别标签统一水平**（10 个类别在 17 cm 内放得下），旋转 45° 会让 OCR 词框互相压叠，制造无穷假阳性。
6. **几十上百个细标签不要塞进图**：把 165 个"情境-模块对"改成"按情境的一致性分布（散点+中位横杠）"，逐条明细转 **Supplementary Table**（审稿人明确接受这一做法）。
7. **图内用短名 + 图例文件给映射**（IGF_INSR_AXIS→IGF_INSR），并在 legends 文件里写明展开规则。
8. **避免用 " — " 分隔**：破折号会被 OCR 读成独立记号并与相邻词框相撞 → 改冒号或括号。
9. 分隔线/参考线/误差棒被 OCR 读成 `-`/`+`/`5` 属常态假阳性，不要据此改图。

## 3. ggplot 陷阱（本项目真实踩坑）
- `geom_col(aes(x = factor_label, y = numeric))` 才是横向柱正确写法；写成 `aes(x = numeric, y = reorder(factor,...))` 等于把**因子当柱高**，ggplot 会打印 `Removed N rows containing missing values` 并**丢弃全部数据**（图空白）。
- 用 `coord_flip()` 后，取值范围要设在**翻转后的轴**上（`scale_y_continuous(limits=...)`）；在离散轴上用 `scale_x_continuous(limits=...)` 会直接报错。
- 因子/字符列在写 CSV 时会被读成字符串 → 求中位数/相关前一律 `as.numeric(as.character(x))` 并 `is.finite()` 过滤。

## 4. 每次改图后的流程（不可省）
1. 重新渲染 → 2. 跑 `scripts/figure_qa_pixel.py <fig_dir>` → 3. 把**具体数字**写进回复（"4 图 0 裁切、0 碰撞、17.0 × ≤24 cm"），不要只说"看起来没问题" → 4. 若仍有候选，先按第 1 节的假阳性规则复核再改。
**诚实边界**：机器检查覆盖几何/裁切/碰撞，不等于人眼审美判断——回复里要写明"最终视觉确认建议作者目检一次"。

## 5. 审稿人说"图里拼错了"但你找不到 → 先判定是不是**缩放伪影**

> 来源：2026-09 胃癌综述 Frontiers 大修。审稿人写 `Figure 1 uses "GCPROVE" instead of "GC-PROVE"`。

先做三连取证，**再决定要不要改图**：

```bash
# ① 证明我方从未改过图（与上一版逐字节比对）
for f in figures/*; do
  old=<prev>/figures/$(basename "$f")
  [ "$(sha256sum "$f" | cut -c1-16)" = "$(sha256sum "$old" | cut -c1-16)" ] \
    && echo "same $f" || echo "DIFF $f"
done

# ② 证明脚本里没有错拼 → 0 命中说明不是我方产出物的问题
grep -rl "GCPROVE\|CosMix\|Genefomer\|IncRNA\|Cauton" --include="*.py" .
```

本项目结果：**52 个绘图脚本全部写 `GC-PROVE`**，9 张图（含 `_reference_` 版）OCR 全部读出
`GC-PROVE`，27/27 文件 SHA256 与上一版一致。⇒ **文件里不存在这个错字。**

### 5.1 多显示宽度 OCR —— 复现审稿人看到的画面

审稿人看的是**缩略图**。按不同显示宽度缩放后再 OCR，就能复现"细连字符消失"：

```python
for width in (1735, 900, 600, 420):        # 原图 → 缩略图逐级
    crop = img.crop(box)                    # 只裁标签所在区域
    s = width / img.size[0]
    crop = crop.resize((int(crop.size[0]*s), int(crop.size[1]*s)), Image.LANCZOS)  # 模拟显示缩放
    crop = crop.resize((crop.size[0]*4, crop.size[1]*4), Image.LANCZOS)            # 再放大供 OCR
    # → tesseract --psm 6
```

实测（同一条 `GC-PROVE gateway`）：

| 显示宽度 | 旧图 | 新图 |
|---|---|---|
| 1735 px | 清晰 | 清晰 |
| 900 px | 清晰 | 清晰 |
| 600 px | 清晰 | 清晰 |
| **420 px** | ⚠️ **开始崩**（`Probiien anchoring`） | ✅ 仍清晰 |

⇒ 旧图 420 px 即损坏，**"小尺寸下字形丢失"这条机制成立**：审稿人的反馈不是幻觉，
只是把"看不清"表述成了"拼错"。**先证明这一点，才有底气既改图又不认不存在的错。**

### 5.2 修法：把标签放大，让细连字符在小尺寸下存活

```python
# 只改这几行；★ 白框必须同步加宽，否则文字出框
draw.rounded_rectangle((533, 686, 1202, 916), radius=40, fill="white",
                       outline="#222222", width=7)              # 原 621×210 / width 6
draw.text((868, 772), "GC-PROVE gateway", font=bold(46),       # 原 bold(34)
          fill="#111111", anchor="mm")
```

要点：
- **只重绘被投诉的那一张**：复制绘图脚本，`main()` 里只保留 `redraw_figure1()`，
  输出目录改到本轮工作目录；其余图保持 SHA256 不变——这样回复里才能说
  "只有 Fig1 做了可读性调整"。
- 面板内其他文字若跟着下移，**同步调 y 坐标**，避免压框。
- 改完**重跑 5.1 的多宽度 OCR**，把"从全分辨率到 420 px 均清晰"作为回复证据。

### 5.3 回复信怎么写（接收意见，但不认不存在的错）

> ❌ 不要写"我们没有这个错误"（顶撞）或"已修正拼写"（不实）。
> ✅ 写：「按审稿人提示复查了全部图件与图注。`GC-PROVE` 的连字符在窄显示宽度下过细，
> **已将 Fig1 的框架标签加大并加宽承载面板**，现从全分辨率到 420 px 显示宽度均清晰无歧义。
> Fig2–5 未改动。」

每一句都属实，且意见被真正关掉。同类措辞适用于其它"审稿人报了一个我方文件中不存在的
拼写/格式问题"的情形（先取证 → 找到最可能的显示机制 → 做最小可验证改进 → 如实描述）。
