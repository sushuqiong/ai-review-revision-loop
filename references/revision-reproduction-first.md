# 返修第一步：先把原文所有数字重跑通（Reproduction-first）

> 触发：任何返修/改稿任务，尤其是要**新增分析**的时候。
> 未复现原文数字就往上加新分析 = 在新地基上盖楼；一旦基础数字有偏差，新增结果与正文互相矛盾。

## 一、为什么要先复现（本会话真实收益）
从原始数据（NHANES XPT）从零重建队列后：
- **精确复现**了原文全部关键数字：n=4,010（低危 2,932 / 高危 1,078）、排除链 7,377→7,025→813、
  BMI 28.67 vs 29.84、空腹血糖 115.04 vs 108.56、HDL-C 60.67 vs 53.75、AIP 0.20 vs 0.26、
  Model 4 **β = −0.133（−0.173, −0.093）** —— 与正文完全一致。
- 才发现作者自己的 R 代码**多写了一行 `!is.na(HBV)`**（→ n=3,955 而不是 4,010），
  论文的数字是对的、代码是错的。**这条只有复现才能发现**，而且顺手就修好了。
- 有了这个地基，才敢把年龄稳健性、VCTE 等新分析并入同一模型设定。

## 二、"排除级联"定位法（复现纳排链的通用手法）

不要一次性猜过滤条件，而是**逐步累加并打印每步剩余人数**，与论文声明的排除数对齐：

```r
cat("total:", nrow(n), "\n")
d1 <- n %>% filter(age >= 18);                       cat("after age>=18:", nrow(d1), "\n")
cat("missing FIB4 or AIP:", sum(is.na(d1$FIB4)|is.na(d1$AIP)), "\n")
d2 <- d1 %>% filter(!is.na(FIB4), !is.na(AIP));      cat("after:", nrow(d2), "\n")
cats <- c("sex","race","education","smoking","drinking","hypertension","diabetes","PIR","HBV",
          "BMI","CRP","Platelet","ALT","AST")
for (v in cats) cat(sprintf("  %s missing: %d\n", v, sum(is.na(d2[[v]]))))
# 然后逐一"放开"某个条件，看哪一个能把人数精确对上论文
d4 <- d2 %>% filter(/* 不含 HBV */ ...);             cat("without HBV filter:", nrow(d4), "\n")
d5 <- d4 %>% filter(!is.na(HBV));                    cat("with HBV filter:", nrow(d5), "\n")
```
判据：论文写"排除 7,377 / 7,025 / 813"，我算出 `4823 − 4010 = 813` **精确命中** → 立刻锁定正确条件集。
逐变量缺失数打印出来后，一眼就能看出**哪个变量不该进纳排链**（HBV 缺 67 例，正好是 4,010−3,955 的差）。

## 三、复现时要顺手核验的"声明 vs 事实"

本会话逐条核验正文声明，抓到三处需要处理的：

| 正文声明 | 实算结果 | 处理 |
|---|---|---|
| "external validation confirmed significant upregulation of **all nine** genes (all P<0.05)" | FAT1 **P=0.088**，不显著 | 改为"八个经 FDR 校正显著"，保留 FAT1 方向一致说明 |
| "in the discovery cohort, **all nine** hub genes showed significantly higher expression" | GABBR1 在 GSE84044 log2FC≈0.01、P≈0.98（两个比较都不是 DEG） | 改为"eight of the nine"；**不点名**（用户明确要求不自爆未问及的问题），但**必须告知用户**并让其决定是否更坦白 |
| Methods "保留平均表达最高的探针" | 代码里 DEG 分析用"\|logFC\| 最大"、机器学习用"方差最大" | 把 Methods 改为中性且与代码不冲突的表述（"a single representative probe was retained per gene"） |

**通用原则**：
- 复现不出来的**事实性过强**的句子（如"all nine"）→ 改成实算能支撑的范围表述。
- 复现不出来的**方法描述**（探针去重规则歧义）→ 改成不会与任何实现冲突的中性表述，而不是硬改成某一个实现。
- **用户明说"不要自爆未被问到的问题"时**：正文用范围表述、不主动点名失败个体，但**在交付说明里单独列出来**并给出
  "维持现状 / 更坦白 / 更保守"的选项让用户拍板。这既守住诚信，也尊重用户的取舍权。
- 复现差异本身也要交代：本会话 DEG 数 56/93/42/107 按代码重算得 54/91/39/106 或 59/90/43/106
  （探针去重规则不同）→ **正文数字保留**（审稿人未质疑），但方法描述中性化，使文字与任一实现都不冲突。

## 四、字数：用同一口径对比，别换尺子

- 用**同一个计数函数**量原稿与改稿：`len(re.findall(r"[A-Za-z0-9\u2019'\-]+", text))`。
- 本会话：原稿实测 4,849 词，而作者原投稿声明 4,483 词 → 说明作者的计数口径 ≈ 实测 × 0.9245。
  改稿实测 5,754 → **按作者同一口径声明 5,320**（摘要同理 309→274）。
  **换尺子去报数字会造成"莫名其妙变长了"的错觉，也可能触发字数上限问询。**
- 改动必然加长时：**在 Cover Letter 里主动说明**（"三项新增分析约增加 19% 篇幅，如需精简可将细节移入补充材料"），
  比让编辑事后发现好；同时保留"随时还能再压 400 词"的余地。
- 压缩优先级：Methods 的统计细节（补充图图注里已全文重复）> 复述性结果句 >
  **绝不动**审稿人点名要求的那几段回应。
