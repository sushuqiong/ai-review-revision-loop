# 一致性、尺度与跨文档同步核查（复合指标流行病学稿件）

来源：课题2 GLM7×胆石症 v12→v13→v14 三轮 GPT6 审稿修复中被审稿人抓出的真实缺陷。
每条都写"审稿人怎么抓的 + 正确做法 + 验证方式"。

## A. 复合指标的重参数化陷阱（"成分 ≈ 整体"多半是代数，不是发现）

若指数是成分的代数之和，例如 `GLM7 = M + log10(age) + log10(BMI)`，其中
`M = metab = log10[空腹血糖 × 胰岛素 × TG × LDL/HDL]`：

**当回归模型已把 log10(age)、log10(BMI) 作为独立线性项放入时，"用完整指数"与"用其余项 M"
是精确重参数化**——同一线性空间、同样的拟合。三队列实测：`|Δb| ≤ 7e-15`、`ΔlogLik ≈ 0`、
共同尺度 OR 比 = **1.000000**。

⇒ 因此"完整指数 vs 代谢成分 OR 比≈1"在含 age/BMI 的框架下**很大程度由数学结构决定**，
不能当作独立的经验发现或生物学结论。

必做核查（写进方法与结果）：
1. 加一个 **log10(age) + log10(BMI) 作为独立线性项** 的框架（记为 Frame A），报告系数恒等性；
2. 明确哪些框架是精确的、哪些只是近似：

| 框架 | age/BMI 形式 | OR 比（三队列） | 性质 |
|---|---|---|---|
| A | log10 独立线性项 | 1.000000 | 精确重参数化 |
| B | 线性 age + 线性 BMI | 1.020 / 1.002 / 1.010 | 近似（数据范围内 log 近似线性）|
| C | RCS age + RCS BMI | 1.007 / 0.999 / 1.002 | 近似 |
| D | 不含 age/BMI（M3）| 1.079 / 1.176 / 1.118 | 未做该分解（指数定义差异）|

3. 表格标题定位为 **"index interpretation and scale sensitivity"**，而非"生物学发现"；
4. 摘要 `equivalent associations` → **`numerically similar conditional associations`**；
5. **删除"去掉组成项 ⇒ 成分与 age/BMI 统计独立"的暗示**——代数拆分 ≠ 统计独立。

## B. 共同增量尺度换算的三条硬规则

把 OR 换算到共同增量（如"1 个 P 系列 SD = 0.7187 原始单位"）：`OR_common = OR_own^(inc/SD_own)`。

1. **OR 与 SD 必须来自同一个分析样本。** 本轮真实事故：§3.5 报告的 N3 共同尺度值
   `2.272` 是用**已被取代的 20–74 岁子样本**（M3=2.130, SD=0.6623）算的，而正文展示的是
   **当前全年龄样本**（M3=1.996, SD=0.6569），正确值应为 `2.130`。
   审稿人会怎么抓：**换算后的区间隐含跨过 1，而源估计并未跨 1**——不可能，因为换算不改变显著性。
2. **换算是重参数化：单个估计的 P 值与显著性不变。** 必须在文中写明（"Converting only the increment scale
   is a reparameterization that leaves every P value … unchanged"），否则审稿人会怀疑混了样本。

3. **但"换尺度不改 P 值"只对单层估计成立，对跨层交互检验不成立**——这是 v15 被审稿人
   逼出来的一条，务必分清：

   - **H0_A**：各层**各自 SD 标准化**后的系数相等（per-layer z-score；比较"标准化效应"）
   - **H0_B**：各层**同一原始增量**（如统一除以 P 期 SD）的系数相等（比较"同一份原始暴露"）

   两者是**不同的零假设**。三队列实测（同一个合并设计、同一共同协变量集）：

   | 框架 | H0_A（各期自身 SD） | H0_B（统一共同增量） |
   |---|---|---|
   | 总关联 | F=6.13 (2,79), P=0.0034 | F=6.53 (2,79), **P=0.0024** |
   | M4 | F=3.27 (2,77), P=0.0435 | F=3.27 (2,77), **P=0.0432** |
   | P vs L | F=1.49 (1,32), P=0.230 | F=0.56 (1,32), **P=0.459** |

   期特定 OR 会随口径整体上移（SD 较小的层上移更多）：L 1.570→**1.641**、N3 2.213→**2.385**，
   而作为分母基准的 P 期不变（1.779）。

   **做法**：正文**两个口径都报**，按主诉选择主口径（若主旨是"同一原始暴露在三期效应是否相等"→ H0_B），
   并明写"两口径在是否拒绝异质性零假设这一点上定性一致"。**不要**只报一个口径却声称另一个也成立。
3. 任何队列重建/样本变更后，**所有派生值必须从当前样本重算**，禁止沿用上一版换算结果。

## C. 批量编辑后的跨文档同步（每轮都会重犯的失败模式）

批量替换、标题同步、S 编号重排、docx 自动构建**必然引入新缺陷**。v12→v13→v14 实测到的：

| 症状 | 具体案例 |
|---|---|
| 标题漂移 | 主稿与补充材料仍是旧标题，只有投稿包换了新标题 |
| 替换产生重复/断句 | "…listed in Table 3 of the main text **and in Table 3 of the main text of this file**; the underlying estimates are given in the source table the …"（重复+缺谓语）|
| 编号过期 | 主稿 S 清单写 S2=基线特征/S3=精确 P/S5=空腹敏感性，而补充材料实际 S2=样本推导/S3=20–74 比较/S5=bootstrap 审计；残留 "Original Table S7" |
| 内部痕迹泄漏 | 补充材料出现构建脚本名 `_build_supp_docx_v14.py`、数据源名 `01_数据/v14_*.txt`、`figS3_forest_v13.tsv`、版本串 `(the v13 M4)` |
| 中文残留 | 表单元格 `step0 (仅常数)`、`step6 +(BMI) = 完整M4` |
| 重复段落 | 两轮替换各写一遍可用性声明，留下两条近似句 |
| 表值错位 | Table 7 的 P 行填了"完全线性 M4"值（1.326）却挂在"age spline + linear BMI"行下，应为 1.284 |
| **补充表双份 + 双套 S 编号**（v15 新增）| 主稿**内嵌**了 4 张补充表（设计顺序/纳排/桥接/L 逐步），而独立 `Supplementary Materials` 文件里也有这些表——两处并存且**编号方案不同**（主稿 S1=设计顺序…S7=bootstrap；独立文件 S1=变量映射…S9=TG 桥接）。正文 `Table S1…S8` 交叉引用与独立文件对不上 |
| **制图脚本里的硬编码 override 泄漏进正文**（v15 新增）| `_make_supp_figs_v13.py` 里有 `override = {("N3","dx_nosx"): (2.506, 1.710, 3.672)}`，而源 TSV 真值是 `2.518403 (1.715231–3.697668)`。这把**伪造值**带进了图、正文表格与段落。抓法：值在**任何**本版输出文件里都找不到 |

**每轮批量编辑后的固定程序**（全部可脚本化）：
1. 从 docx 枚举**实际**的 Table S*/Figure S* 标题，与主稿声明段逐条 diff；
2. 全部文件扫描禁用 token 表：版本串（v13/v14）、`_build`、`_supp_out`、数据目录名、
   `[Author]`、`to be completed`、`revised`、`Response to`、`Original Table`、`GPT`；
3. **所有表单元格**扫 CJK（正文干净不代表表格干净）；
4. 重数摘要词数，并重建 Title page 上的所有元数据；
5. 标题变更后，断言该标题字符串在**全部 N 个文件**中存在且一致。

6. **补充表只放一份**：主稿**不应内嵌**补充表——它们属于独立的 `Supplementary Materials` 文件。
   删法：按 body 顺序遍历，遇到 `Table S<n>. …` 标题段就删该段 + 紧随的 `w:tbl` + 其表注段，
   直到遇见下一个 `Table `/`Figure `/`References` 开头的段为止；删完断言主稿表数 == 主表数。
   删掉内嵌表后**必须重映射正文引用**：用两遍替换（先 `Table S1`→`Table @@S4@@`，
   全部映射完再脱 `@@`），否则会连锁覆盖（S1→S4 之后 S4→S8 会把刚写好的 S4 再吃掉）。
   最后重写声明段，按**独立补充材料的实际顺序**列出 S1…S9，并断言
   `all(f"Table S{i}" in full for i in 1..N)` 且声明段内无重复编号（v15 曾出现两个 "Table S8"）。

7. **审计制图/构建脚本里的硬编码数值**：`grep -nE "override|hardcod|manually|TODO|FIXME" *.py *.R`，
   凡 `override = {...}` 或直接写死的估计值一律改为**从结果文件读取**。
   判断真伪的通用判据：**该值必须能在本版某个输出文件（RDS/TSV/CSV/TXT）里找到**；
   找不到就是污染。改完后把图与正文里所有出现过该值的位置一起改，并重跑图件自检与 docx 重嵌。

## D. 词数与元数据口径

- **摘要词数按两种口径各数一次**：含结构标签（Background:/Methods:/…）与不含。
  部分期刊计标签 → **按更严的口径达标**（压到含标签也 ≤350）。
- Title page 上的元数据（摘要词数、正文词数、表/图/参考文献数）会随改稿漂移，
  **每轮从构建出的 docx 重算**，不要沿袭上一版数字（本项目实测：声明的 9,112 词 vs 实际 10,670）。
- 跨文件数字一致性：选一小组"锚点数字"，断言每个都出现在应当承载它的每组文件里
  （主稿 / 补充 / Cover letter / Title page）。

## E. 不必依赖视觉模型的廉价核查

- 内嵌图的数量与顺序：枚举 `w:drawing` / `a:blip` 元素，并回溯最近的 `Figure N.` 标签；
- 裁切/贴边：PIL 扫描四边留白 > 0（能抓住被裁的标题）；
- 引用首现序：正则抽 `[n]`，断言首次出现顺序严格递增且无孤儿；
- 三线表：检查 tblBorders（顶/底 sz=12、表头下 sz=6、无竖线）。

> 注意：vision 类工具在本用户环境多次误判，**图面美观度与文字完整性以源码/坐标/像素为准**，
> 但"某文件里是否存在某字符串"这类判断永远用程序化 grep，不要用视觉模型。

## F. 创新性定位：先查是否已有正式评论（comment / correspondence）

**每轮定稿前必须做一次**：搜索**被评价指标/方法**的评论文献（`Comment on: "<原指标论文标题>"`、
`correspondence`、`letter to the editor`），而不只是搜指标名本身。

真实教训：某指标 2026 年已有正式评论信（Adv Sci），其三点——①对数指标与线性变量的 OR 不可直接比较，
应按 per-SD/per-IQR 标准化后比；②年龄作为组成项可能驱动指标表现；③应比较指标 vs 年龄（或年龄+BMI）的 AUC
——**恰好就是本文的全部核心论点**。稿件此前**未引用**，导致"创新性"定位站不住。

**处理模板**（不是撤回，是重定位）：
1. **引用该评论**（正文引言与讨论各一处）；
2. 贡献重述为：**"在这些已被提出的方法学疑问上，于 <具体结局>、<时期/人群>、复杂抽样下提供实证检验"**；
3. **删除**把"发现年龄有贡献""发现 OR 比较受尺度影响"当作主要创新的表述——这些已属他人观点；
4. 若某张表（如代数分解表）本质是他人质疑的回应，可保留但**压缩**，不要在摘要/结果/讨论/结论四处重复同一结论。

**自查问句**：本文最核心的那句话，是否可能已经写在别人的评论信里？如果是，卖点就不是那句话，
而是**你用什么数据、什么设计、什么稳健性把它检验到了什么程度**。

### F2. 不止搜"评论信"——还要搜**同结局/同指标的已发表实证比较**（v17 新增）

v17 轮踩到的另一种情形：卖点不是被**评论信**占掉，而是被一篇**已发表的实证论文**占掉。

实例：本文的卖点之一是「复杂指标不一定优于简单指标（BMI）」。审稿人指出——
**已发表的 LAP 研究（Li X, Wang J, Leng K, NHANES 2017–2020）已经报告
`Ln-BMI (AUC = 0.746)` 优于 `Ln-LAP`**，因此该结论**不是新发现**。

⇒ 定稿前**两种检索都要做**：
1. `Comment on: "<原指标论文标题>"` / correspondence / letter —— 方法学质疑类（见 F）；
2. **该结局 × 该指标/其比较指标**的已发表实证研究 —— 结论类
   （检索式例：`<结局> AND <指标名> AND (comparison OR superiority OR "vs BMI")`）。
   若有，必须引用，并把贡献重述为**本文的设计优势**（跨时期 / 复杂抽样 / 同一样本内比较 /
   关联与增量判别的区分），而**不是**那个已被别人报过的结论本身。

**收敛轮的心态**（审稿人原话）："创新性也要保持克制……本文更有价值的贡献是，
对 <指标> 进行**跨时期、复杂抽样下的系统复核**，并**展示关联与增量判别之间的区别**。"
⇒ 越到后期，**越不要把"某个比较结论"当卖点**，而要把"系统复核 + 方法学辨析"当卖点。

## G. 汇总/合并估计的报告口径（审稿人必问的两条）

### G1. 高 I² 时不要只报固定效应合并值
把各层估计做逆方差合并时，若**层间异质性很大**（实测 I²=87.3%、Q 检验 P<0.001），
只报一个固定效应 pooled OR 会被直接质疑"为什么不报随机效应"。

- **做法**：报 Q、I²、**以及随机效应（DerSimonian–Laird）合并值与 τ²**；
  或用一句话说明为何固定效应是可接受的主汇总。
  实测写法：`fixed-effect pooled OR 1.814 (1.679–1.960)` **＋** `random-effects 1.833 (1.473–2.281); τ² = 0.0325`。
- **可交换性必须表态**：若各层是**不同年代、不同判定方式**的调查，合并值只能定位为
  "对层特异估计的汇总"，**不能**当作共享真值的估计——这句话要写进正文或表注，
  否则审稿人会认为你在隐含假设三期可交换。
- 更稳妥的替代：只报 Q/I² 与层特异估计，**不给**合并值。

> **收敛轮的重要修正（v15→v16 实测）**：上面这套"补随机效应对照"是**早期轮次**的做法——
> 先把口径补齐。但到了**后期收敛轮**，审稿人会反过来说这些附加分析"让文章再次向多个方向展开"，
> 要求**把固定/随机效应合并 OR 移入补充材料，甚至直接删除**，
> 因为"三期各自效应 + 交互检验已经能表达主要信息"。
>
> **判断法**：本轮的审查意见是在**质疑口径**还是在**要求收敛篇幅**？
> 前者→补齐全套；后者→**下沉或删除**，正文只留层特异估计与交互检验。
> 不要在收敛轮里新增分析种类——审稿人原话："当前核心结论不需要推倒重来，
> 也没有必要再增加机器学习、新结局或一批零散敏感性分析。"

### G2. 描述性比较表必须声明探索性、不做多重比较校正
一旦在正文或补充材料里放"纳入 vs 排除""分层 vs 全体"这类**成组比较表**（实测：40 项比较中 10 项 P<0.05），
审稿人一定会问是否校正了多重比较。

- 固定加一句（表注 + 正文相关处各一处）：
  `"These comparisons are descriptive and exploratory; no multiplicity adjustment was applied, and the
  individual P values should not be interpreted as confirmatory tests."`
- 与既有的"主要分析未做多重校正"声明**分开写**：主分析的重复性论证与描述性表格的定位不是一回事，
  审稿人会把两者分开追问。
- 同时检查全文是否已声明主要分析为探索性/未校正——两条声明都要在，缺一条就会被追。

### G3. 样本限制型敏感性分析的精度代价——**只说到位，不要展开成一整段量化**

**本条的早期版本写"必须量化精度损失、可复用 log-OR 区间宽度比"——下一轮审稿人（GPT6，v15→v16）
明确要求把这一整段删掉**，理由：它让文章"再次向多个方向展开"。修订如下。

- ✗ **不要再写**这样的段：逐层列出区间宽度比（P 1.00/1.00、L 1.13/1.19、N3 1.04/1.04）
  + "均值加宽 6.8% / 受影响层 10.1%"。审稿人判为不必要的铺陈。
- ✓ **只保留三句事实**，每句一个要点：
  1. 年龄限制**改变了分析人群**（给限龄后的各层 n）；
  2. 子样本内**重新标准化改变了"每 1 SD"的含义**（给全年龄 vs 限龄的 OR 对照，
     如 N3 M3 `1.996` → `2.130`）；
  3. **P 值跨过 0.05 不能单独证明发现了真实关联**。
- ✓ 三句之外若要一句收束：**较小的 P 值来自"点估计位移 + 精度变化"两者，而不是关联变强**。

**一个连带的事实错误（务必自查）**：不要说"实际受年龄限制影响的**只有**某些层"。
只要某层有限龄前后两个样本，它**就**受到了影响——即使其 CI 宽度几乎没变。
判据用**各层 ≥75 岁人数占比**（实测 P/L/N3 三层的占比接近，L ≈10.5%、N3 ≈10.6%），
而不是"CI 有没有变宽"。**"当代样本在 ≥75 岁很稀少"这类笼统表述同样缺依据，删掉。**

⇒ 通用原则：**敏感性分析的"局限/代价"用 2–3 句说清即可，一旦写成带多列数字的量化段落，
后续审查会把它当冗余要求删除。** 把量化数字留在补充材料，正文只留结论性事实。

## H. 压缩后的"信息保全"审计（用户必问："没有丢失主要信息吧？"）

对手稿做大幅压缩（实测 v15→v16 正文 7,742 → 6,995 词，约 −10%；更早轮次 −20%+）后，
用户的第一个问题几乎必然是**"有没有丢主要信息"**。不能只答"我删的都是冗余"——要**做一次可复算的审计**。

**审计方法（无需视觉模型，全程序化）**：

```python
# 逐版对比：压缩前 vPrev vs 压缩后 vNew
def load(p):
    d = Document(p)
    paras = [x.text.strip() for x in d.paragraphs if x.text.strip()]
    tabs  = [[[c.text for c in r.cells] for r in t.rows] for t in d.tables]
    return paras, tabs

prev_p, prev_t = load(PREV)      # 上一版交付稿（例如 课题2v14/05_论文投稿/…_v14.docx）
new_p,  new_t  = load(NEW)       # 本版交付稿

import difflib
sm = difflib.SequenceMatcher(None, prev_p, new_p)
print("相似度", round(sm.ratio(), 4))
for tag, i1, i2, j1, j2 in sm.get_opcodes():
    if tag != "equal":
        print(tag, "prev[%d:%d] -> new[%d:%d]" % (i1, i2, j1, j2))
        for t in prev_p[i1:i2][:3]: print("   -", t[:100])
        for t in new_p[j1:j2][:3]: print("   +", t[:100])
print("表：", len(prev_t), "->", len(new_t))
```

**判定规则（逐条给出"哪去了"，而不是笼统说没丢）**：

1. 用 `SequenceMatcher` 的 opcodes 列出**全部**增删改，逐条归因；
2. 每条 `delete` 必须能归入下列之一，否则视为**真丢失**：
   - 移入补充材料（在 supplementary docx 里 grep 到原文片段）
   - 删除的是**修订过程痕迹**（"corrected"/"previously"/版本号/"v12"）
   - 删除的是**重复表述**（同一结论在正文出现 ≥2 次，只留一处）
   - 措辞精简（语义等价、句子变短）
3. **必查的"高风险清单"**——这些最容易被顺手删掉，且删了就是实质损失：
   核心结果数值、方法学声明（bootstrap/加权/多重比较）、限制条款、结局分母、
   稳健性分析的存在性、作者/基金/声明/CRediT/缩写表；
4. 表数变化必须能解释（本例 5 表 → 7 表，是"把技术细节移入补充"后的净增/重排，而非丢表）；
5. 结论用**一句话**给：`无重要信息丢失；压缩主要削掉解释性冗余（列举 2–3 类）`，
   并给出**补充材料反而净增**的对照（若有），这样回答才有分量。

> 反面模式：只回答"我删的都是重复的"而不给逐条归因——用户会继续追问，且无法证伪。
