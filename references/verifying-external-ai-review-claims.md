# 接收外部 AI 审稿意见：先程序化核实断言，再决定照做多少

## 触发
用户整份转发外部 AI 的审稿文档（GPT6 / Claude / 腾讯 Hy4 等），并说
"**我完全同意执行它的观点**"。这时容易直接照单全改——风险是其中混着
**不成立的技术断言**或**把审稿人主张当成期刊政策**的条目。

## 流程（本项目 15 条意见实测有效）

### 第 1 步：把可核实的断言写成脚本一次性核验
不要逐条读着改。先把"可核实的断言"抽出来，写一个脚本扫正文 + 表格单元格 + PDF 文本层，
产出 **意见 → 原稿实际 → 判定（真/假）** 三列表。

本项目核验的 11 条编辑类断言（**全部为真**，故可放心全量执行）：
| 断言 | 判定 |
|---|---|
| Background 首段有重复句 + 错标点 `approach., as do the ACC/AHA` | 真 |
| 正文残留字面量 `# Results` | 真 |
| 引用了不存在的模型名（`M-1`，模型只有 Base/M0/M1/M2） | 真 |
| 千分位逗号（实测 168 处 / 97 个不同数字） | 真 |
| 分母互相矛盾（同一队列出现 14,281 / 14,512 / 7,817 / 7,972…） | 真 |
| 缺 Research Insights / List of abbreviations / Graphical abstract | 真 |
| LLM 声明只在 Declarations、未写入 Methods | 真 |
| 标题过长（实测 21 词 / 144 字符） | 真 |

正则速查（扫 docx 正文 + 表格，再扫转出 PDF 的文本层）：
```python
"unclosed **":            lambda t: t.count("**"),
"'Table 6.**' pattern":   lambda t: len(re.findall(r"Table \d\.\*\*", t)),
"ghost variable name":    lambda t: t.count("wgt11"),          # 换成被引用的名字
"falsifiable claim":      lambda t: t.count("weights were not available"),
"comma thousands":        lambda t: len(re.findall(r"\b\d{1,3}(?:,\d{3})+\b", t)),
"internal version tags":  lambda t: len(re.findall(r"\bv1[0-9]\b", t)),
"placeholder brackets":   lambda t: len(re.findall(r"\[(?:Author|Affiliation|Institution|email|Corresponding|funding)", t, flags=re.I)),
"duplicated word":        lambda t: len(re.findall(r"\b(\w+)\s+\1\b", t, flags=re.I)),
```
注意假阳性：`duplicated word` 会命中表格里的数字列（`0 / 0`）；
`nan` 会命中英文词内的 `u**nan**swered`；`Supplementary Table S` 的顺序检查要先
把所有空白压成单空格再匹配，否则被换行截断而误判"顺序错乱"。

### 第 2 步：按"是否改变科学主张"分流
- **低风险且可逆**（去千分位逗号、统一术语、补缩写表、修重复句、去内部版本号：
  可批量执行）。
- **会改变科学主张或数字**（换主估计量、改人群定义、改权重策略、放宽/收紧排除条件：
  **必须先重算核实再动**，且要在同一条新管道里复现已发表的数值才算重建忠实）。
- **审稿人对期刊政策的断言**：先去期刊原始要求页逐字核对。
  核实不到就不要写成"期刊硬性要求"，如实写"审稿人提出、未在页面上证实、已按低风险处理"。
  本项目实例：**"该刊不建议用逗号表示千位数值"未能证实**。

### 第 3 步：报告里给"意见 → 原稿实际 → 处置"对照表
用户要的是这种三列表（而不是"已按意见修改"的笼统汇报）。
每条要能追到脚本的一次真实输出或一次真实拟合。

## 陷阱
- **审稿人给的数字不能直接抄进新稿**。本项目外部 AI 的"已回应某关切"补充表是脚本
  **硬编码写进 md** 的（引用了不存在的权重变量名、HR 与实测差 0.02、I² 差一倍）。
  凡"声称已解决"的表，一律回到源数据重算——**发现假回应表本身就是高价值交付**。
- **用户说"完全同意"不等于放弃核实**。核实后再全量执行，比先执行后返工便宜。
- 用户可能对某个"二选一"的决断不回复（clarify 收到空回复）。此时**不要阻塞**：
  先用数据算清两条路的差异（如加权 vs 未加权只差 0.004），选"改动更小且更自洽"的那条，
  在报告里**显式标注这是你自主拍板、可回退**，并给出回退成本。用户要的是推进，不是等待。
